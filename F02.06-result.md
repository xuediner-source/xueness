## What was built

The barrier invariant (only explicitly concurrency-safe calls run in parallel; everything else is a serial barrier; approval suspension blocks later side effects; result order preserved) already held on both sides — per the brief, no parallelism gap was claimed. What was missing — a **configurable concurrency cap** and **safety-metadata/dependsOn vocabulary** — is now a single shared scheduler.

### New module: `ts/packages/tool-bridge/src/batch-scheduler.ts` (106 lines)

- `DEFAULT_BATCH_CONCURRENCY = 10`.
- `ScheduledCall` — vocabulary: `id`, `concurrencySafe`, `readOnly`, `mutating`, `destructive`, `dependsOn`.
- `parallelEligible(call)` — eligible only when explicitly `concurrencySafe === true` **and** not `destructive`; `readOnly`/`mutating` alone never qualify (explicit-only parallelism).
- `planBatches({ calls, concurrencyCap?, suspended?, eligible? })` — pure, deterministic planning: consecutive eligible calls form parallel groups up to the cap (integer ≥ 1, otherwise `TypeError`); mutating/destructive/unmarked calls and any call with a non-empty `dependsOn` are single-call barrier groups; `suspended()` (approval suspension / stopTurn / blocked effects) prevents parallel expansion.
- `runBatches({ calls, groups, execute })` — executes groups strictly in order; parallel groups use bounded workers claiming indices from a shared counter; results are settled by the caller per index, so call/result order is always preserved; `execute` rejections propagate.
- `dependsOn` is accepted vocabulary, defaults to empty, and never gains fabricated edges — mirroring upstream's current `dependsOn: []` mapper output. No DAG is invented.

## Acceptance vs. brief

- "Side-effecting calls are serial barriers" — mutating/destructive/unmarked calls each get a barrier group; a barrier starts only after the previous group fully settles (tested).
- "Safe calls use bounded concurrency" — max in-flight ≤ cap with the worker-claim pattern (tested at cap 4).
- "Result order preserved" — results are written by original call index regardless of completion timing (tested).
- "Only use dependencies actually provided (default `[]`)" — `dependsOn` only forces a barrier when actually declared non-empty; no edges are synthesized (tested).
