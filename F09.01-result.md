# F09.01 Result — 建立记忆 Manifest/Index (Memory Manifest/Index)

- **Status**: Completed
- **Files changed this round**:
  - `ts/plugins/memory/src/memory-index.ts` (new, 207 lines): the hierarchical manifest/index over the three curated tracks (`MEMORY.md` / `USER.md` / `projects/<hash>/KEY.md`).
    - `buildMemoryIndex(root, cwd)` walks each track's `\n§\n` entries — reusing the loader's `entryBodies` head-stripping, so what is indexed is exactly what the whole-track render would show (Python parity, BOM/CRLF tolerated) — and produces one `IndexedMemoryEntry` per entry with a stable id (`track:<sha256[:16]>` of the clipped body), a traceable source (`{ file, entry }`: the track file plus the 0-based position in it) and a content `version` (`sha256[:16]`, changes iff the body changes).
    - Per-entry and per-track caps: bodies clip at `INDEX_ENTRY_MAX_CHARS` (800 code points, visibly marked `…(truncated)`), tracks index at most `INDEX_TRACK_MAX_ENTRIES` (200) entries — the long tail is unreachable by selection anyway.
    - `selectCandidates(index, score, limits)` reduces the index to a bounded candidate set: zero-score (irrelevant) entries dropped, the rest ranked score-desc with id-asc tie-break (deterministic), cut at `maxEntries` (default `SELECT_MAX_ENTRIES` = 12) and `maxChars` total body code points (default `SELECT_MAX_CHARS` = 3000). Every candidate keeps its entry's source and version.
    - `manifestOf(index)` projects a provenance-only manifest — per-track `{ track, file, version, entries, chars }` plus the index version/fingerprint — with no memory bodies at all, so a request can carry source/version provenance without carrying every memory's text.
    - Stat fingerprints: `fileVersion` (`ino:size:mtimeNs`, or `"missing"`) and `indexVersion` give a cheap staleness probe that reads no bodies; `indexStale` compares only the per-track stat versions so a quiet store never triggers a rebuild. Nothing here throws: an unresolvable root yields `{ ok: false, failure }` while a merely missing track reads empty (not failed), matching the whole-track loader's unreadable-track-reads-empty contract.
  - `ts/plugins/memory/src/memory.ts`: `renderTrack` refactored onto a new exported `entryBodies(text)` helper (the same cleaning, `- ` bullet stripping removed) so the indexer and the renderer share one entry-splitting definition; output of `renderTrack` is byte-identical.
  - `ts/plugins/memory/src/index.ts`: re-exports `./memory-index.ts` (and, for F09.02, `./memory-recall.ts`) from the plugin entry, following the established engine-module pattern of `memory-dream-*`.
  - `ts/plugins/memory/test/memory-manifest.test.ts` (new, 6 tests).
