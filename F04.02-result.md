## Design

- **Primary store** (`SqliteSessionStore`, DB file `session-store.sqlite`,
  distinct from the existing optional `session-library.sqlite` mirror):
  one `session` row per journal (complete lossless payload via the
  Python-compatible codec) plus an indexed `session_message` projection
  derived from the F04.01 canonical model (`seq`, `message_id`, `turn_id`,
  `role`, `origin`, `visibility`, `revision`, per-message digest), with
  indexes on `(session_id, seq)`, `turn_id`, `root`, `updated_at` and a
  primary key on `(session_id, message_id)` as the duplicate-identity
  backstop.
- **Transaction boundaries**: every operation runs inside one
  `begin immediate … commit` (WAL, `busy_timeout`, foreign keys). A save
  writes the session row and rebuilds its message index together; a failed
  save rolls both back (tested: an invalid row leaves the previously
  committed revision intact). `update()` is a single-transaction
  read-modify-write. The schema itself migrates inside the same ledgered
  transaction pattern (`schema_migration` with checksums; unknown or newer
  schemas are refused).
- **Publish-after-persist**: `onChanged` fires strictly after the commit —
  a test opens an independent read-only connection inside the callback and
  observes the committed row.
- **Migration** (`migrateJsonJournals`): imports each JSON journal in its
  own transaction and records `(session_id, digest, message_count,
  attachment_count)` in a `json_migration` ledger. Re-running skips
  sessions whose ledger digest matches, so an interrupted migration
  restarts where it stopped. The JSON store is only read — journals are
  never rewritten — so falling back to JSON (or `openStartupSessionStore`
  choosing `"json"`) is always possible.
- **Verification** (`verifyJsonMigration`): per session, message count,
  file-association count (media references + recorded
  `input_attachments` files) and the `canonicalSessionDigest` must match
  between journal and SQLite row; mismatches are enumerated.
- **Startup selection** (`openStartupSessionStore`): JSON until
  `XUENESS_SESSION_STORE=sqlite` is set or a migrated database exists,
  SQLite afterwards — matching the upstream
  `openStartupSessionStore → SqliteSessionStore` shape.

## Contract invariants satisfied (C-SES-02)

- **Writes persist before they are published** — publication callback runs
  only after the transaction commits, verified from a second connection.
- **Restart restores a consistent revision point** — every save is atomic;
  a rejected save leaves the last committed revision readable.
- **Interrupted migration is restartable** — simulated crash after the 2nd
  session: 2 ledger rows survive, re-run imports the remaining session and
  skips the completed ones.
- **Counts and digests agree before/after migration** —
  `verifyJsonMigration` reports zero mismatches and equal message totals;
  file-association counts match (media refs + recorded attachments).
- **Original data is never overwritten** — journal files are byte-for-byte
  unchanged after migration (asserted in the test).
- **Optional mirror failure cannot corrupt the primary store** — the legacy
  JSON-primary + `session-library.sqlite` mirror path is untouched; the new
  primary store keeps its own database file and ledger.
