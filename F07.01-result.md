# F07.01 Result — Config Layer Alignment & Multi-Root Workspaces

- **Status**: Completed
- **Files changed this round**:
  - `ts/plugins/settings/src/layers.ts` (new): upstream-aligned source display and multi-root switching on top of the layered loader. `LAYER_ORDER` fixes merge precedence (defaults < userDefaults < state < workspace < environment < overrides) and `LAYER_SCOPES` maps every Xueness layer onto the upstream system/user/project/env/CLI vocabulary (defaults→system; userDefaults & state→user; workspace→project; environment→env; overrides→cli). `runtimeConfigOverrideMatrix(result)` builds the override matrix: every effective leaf pointer with its winning layer and scope, plus per MCP server the full chain of layers that defined it (winner last). `LayeredRuntimeConfig` reads the non-workspace layers once (state patch cached in the constructor) and `switchRoot` re-applies **only** the workspace layer onto that cached base, exactly like a multi-root client hopping between open roots.
  - `ts/plugins/settings/src/runtime-config.ts`: `RuntimeConfigLoadResult` now carries `layerPatches` — every accepted layer's own patch in merge order, the matrix input. New `statePatch` load option: `undefined` reads the state file as before, a patch reuses a cached read (so workspace switching never re-reads user state), `null` reproduces the invalid-file diagnostic. New `migrateLegacyWorkspaceDocument`: a pre-layering workspace document (`mcpServers` / `enabledPlugins` / `pluginOptions` at the top level) is mapped onto the patch shape **in memory** — the file on disk is never rewritten — and a `workspace_legacy_migrated` diagnostic names what was migrated.
  - `ts/plugins/settings/src/runtime-config-api.ts`: the HTTP runtime-config view now exposes `matrix`, so clients can render where each effective value came from in upstream scope vocabulary.
  - `ts/plugins/settings/src/index.ts`: re-exports `layers.ts`.
  - `ts/plugins/settings/test/runtime-config-layers.test.ts` (new, 3 tests).
