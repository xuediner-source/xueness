## Contract Invariants Satisfied
- **Paid models only with explicit authorization**: without `authorized: true` (plus `authorizedBy` and `grantRef`) the runner never invokes the call port and records every scenario as `blocked` with a blocker; the validator marks any `completed`/`failed` record without a full authorization invalid — mirroring the F00.04 harness checker's `live_model` + `costAuth` rule.
- **Same model/config across scenarios**: the batch carries a single `model` and `configFingerprint` applied structurally to every scenario; per-record drift from the batch model/config is a validation failure.
- **Actual completion/failure with traces**: each record carries its full event trace (per-lane start/complete/fail with timestamps, output excerpt or error detail), raw token usage and billed cost as reported (omitted when unknown, never fabricated), durations, and per-lane error text; a thrown transport error becomes a failed lane, not a crash.
- **No sample counts as success rates**: summaries carry only `{completed, failed, blocked}` category counts; any `successRate`/`passRate`/`coverage`/`percent` field anywhere in the batch or a record is rejected by the validator and by file loading.
- **Representative scenario coverage**: the five required scenarios (edit, long task, concurrent subagents with N-lane fan-out, multi-step workflow, MCP) are first-class scenario ids with lane structure the trace preserves.
