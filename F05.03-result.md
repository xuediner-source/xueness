# F05.03 Result — Foreground Timeout Auto-Backgrounding (C-TOOL-08)

## Deliverable

Bash `auto_on_timeout`: a qualifying foreground command whose deadline
arrives is submitted as a background task alive and keeps running; the task
id, logs and completion notification stay available; explicit background is
unchanged; process ownership moves to the task manager (the parent cancel
link is released at the handoff); cancelling other runs never kills an
adopted task.

## Design

- **Eligibility first, deadline second.** The deadline timer only arms an
  adoption when a task manager exists and `isAutoBackgroundEligible` says
  yes; `sleep …` (the probe of choice for a timeout) must die at its
  deadline instead of occupying a background slot, matching upstream
  `isBashAutoBackgroundEligible`.
- **Live handoff, not a restart.** At the deadline `runProcess` pauses
  stdout/stderr, detaches its `data`/`exit` listeners, removes its abort
  listener (ownership transfer: the parent cancel link is released exactly
  as upstream `node-execution-adapter-lifecycle` does), finishes the
  foreground capture, and passes the paused child to `adopt`. If `adopt`
  returns false (capacity raced away), the tree is killed and the run
  settles as a normal timeout with the output captured so far.
- **Same task lifecycle as explicit background.** An adopted task is an
  ordinary task — id, `exec_output`/`exec_kill`, per-owner visibility, the
  plugin's durable completion notice (`_background_task_notice`), the
  plugin's own background limit, and dispose-on-disable all apply to it.
- **Cancel rules.** Aborting the parent signal after the handoff is a
  no-op for the task; aborting before the deadline still cancels
  (`command_cancelled`); aborting a *different* concurrent run never
  touches the adopted task (`trackChild`'s global set is only signalled by
  the run that owns the child, and the adopted child was handed off).

## Contract invariants satisfied (C-TOOL-08)

- **Foreground timeout ≠ command death** — `echo part1; sleep 30` with
  `timeout_ms: 350` returns at the deadline with `ok: true`, a `bg_…` id,
  `state: "running"`, `adopted: true`, the log paths, and the process still
  alive; `exec_kill` then ends the tree.
- **Not-backgroundable commands die on time** — `sleep 30`, an explicit
  `auto_on_timeout: false`, a run without a task manager, and a full task
  manager (`maxRunning` reached) all settle as `command_timeout` at the
  deadline.
- **Ownership transfer and cancellation hygiene** — parent abort after the
  handoff leaves the task running; a cancelled sibling run never kills the
  adopted task.
- **Id, logs and completion notification usable** — the plugin test drives
  the whole path through `PluginHost`: adoption into the plugin's manager,
  `exec_output` reads, the durable `timed_out` notice reaching the session
  (`bg_…:timed_out`, no command output echoed), and disable stopping the
  adopted task.
