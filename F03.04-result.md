# F03.04 Result — Goal Continuation & Stop Criteria (C-WFL-03)

- **Status**: Completed
- **Deliverable**: Unified contract for budget, verification, pause, completion, proactive continuation and termination reasons; the runner honors terminal stops for the rest of the run.

## Files Changed

- `ts/plugins/planning/src/goal-contract.ts` (new): The unified goal continuation & stop contract. `GoalStopCode` enumerates `complete` / `budget_limited` / `paused` / `blocked` / `waiting_user` / `boundary` / `changed` / `unavailable`; `goalStopDecision` / `goalContinueDecision` build the two decision shapes (continuation stays `exclusive` and tagged `goal_continuation`); `goalDecisionFromRun` maps a settled goal-driver row onto a stop code via the persisted goal status plus reason classification — without altering the driver's settlement; `GOAL_TERMINAL_STOPS` / `stopCodeIsTerminal` define which stops are final; `journalGoalStop` persists `runtime.stopCode` / `stopReason` / `stoppedAt` onto the goal for terminal stops only, never changing the status the driver already settled.
- `ts/plugins/planning/src/goal-extension.ts`: `afterRun` now routes the goal-driver row through `goalDecisionFromRun` and journals terminal stops. Planning only owns the continuation vote when this run actually drove an active goal (`runGoalId`), so sessions queue draining stays free to continue. New `appendTurn` journals the proactive continuation prompt as goal input — `_input_kind: "goal_continuation"`, `_meta_source: "target_continuation"`, `_goal_id` — and refuses to append when the goal is no longer active.
- `ts/packages/agent/src/runner.ts`: C-WFL-03 runner semantics. An extension's explicit `stop` decision is now terminal for the whole run: later extensions' `afterRun` votes never run, no continuation prompt is appended, and the loop breaks. Each run starts by clearing `session.run_stop`, and the loop journals it (`code` / `reason` / `owner`) when a terminal decision, cancellation or the wall-clock deadline ends the rounds; natural exhaustion journals nothing.
- `ts/plugins/planning/test/goal-contract.test.ts` (new): 3 unit tests (decision shapes, stop-code mapping across all eight codes, continuation journaled as goal input rather than a human utterance).
- `ts/packages/agent/test/runner-terminal.test.ts` (new): 4 unit tests (no later round after a terminal stop, `run_stop` journaling matrix, bounded continuations still work without a terminal stop, continuation appended through the owning `appendTurn` hook).

## Contract Invariants Satisfied (C-WFL-03)

- **Automatic continuation preserved**: the existing production chain (goal extension installed by `ts/apps/server/src/agent-service.ts` → `afterGoalRun` driver → runner consumption of the exclusive `continue` decision) is fully retained; the extension now also journals the continuation input so it is never recorded as a new human utterance.
- **Goal active ⇒ auto-continue until a stop criterion**: unchanged driver loop; the unified contract only classifies and enforces its outcomes.
- **No further rounds after budget or user pause**: terminal stop codes (`complete`, `budget_limited`, `paused`, `blocked`, `changed`, `unavailable`) break the runner loop immediately — verified end-to-end: a second extension's `continue` vote never runs and no turn is appended. `waiting_user` / `boundary` stops remain resumable.
- **Stop criteria carry evidence, not text self-assessment**: codes derive from the persisted goal status (settled by the evidence-based driver/verifier — `goal-verifier.ts`, `goal-evidence.ts`) and the driver's structured reason, never from free-form model text.
- **Termination reason is durable**: terminal stops are journaled twice — onto the persisted goal (`runtime.stopCode/stopReason/stoppedAt`) and onto the session (`run_stop`) — so the reason survives the run and is inspectable afterwards; a fresh run clears the stale record.
