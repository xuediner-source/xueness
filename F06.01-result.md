# F06.01 Result — MCP Connection Pool & Lease Generations (C-ADJ-02, pool/lease half)

- **Status**: Completed
- **Files changed this round**:
  - `ts/plugins/mcp/src/runtime.ts`: connection generations and lease lifecycle hardening in `McpConnectionPool`.
    - Every `acquire` that opens a connection stamps a monotonically increasing `generation` per server id (`#generations` map); leases, snapshots and every `mcp_activity` event carry it.
    - Snapshots are published through `#publish`, which never lets a superseded generation overwrite the newest snapshot for its server id (an old entry disconnecting late can no longer clobber the live one's state).
    - An idle entry that died or never connected is retired at acquire time (`#closeEntry`) instead of being revived: the next acquire opens a fresh generation, so dead/dead-on-arrival connections are never handed out as leases.
    - The handshake now re-checks `client.active` after `listTools` — a server that exits right after `initialize` is marked `failed` as a new generation rather than reported `connected` with a stale catalog.
    - `pool.closed` getter plus a guard in the plugin start loop: once the pool is closed (plugin disabled / run shutdown) no new connection is spawned, and `acquire` failures during shutdown no longer abort the run start loop (`.catch(() => null)` per server).
    - Snapshot extended with `generation`, `progressCount` and `capabilities` (declared capability group names only — metadata, never catalog contents).
  - `ts/plugins/mcp/src/client.ts`: `McpClientActivity` gains `"progress"`; `notifications/progress` payloads are recorded as numeric-only `ProgressSignalMetadata` (token/progress/total/observedAt, ring-limited to 32) so activity records store metadata, not free text; `callTool` accepts an optional `progressToken` that rides the request `_meta`.
  - `ts/plugins/mcp/src/index.ts`: start loop stops before spawning anything new once the pool is closed (disabling the plugin mid-start takes effect immediately) and tolerates per-server acquire failures.
  - `ts/plugins/mcp/test/runtime-fixture.mjs`: fixture server records every `initialize` it receives (`MCP_INIT_FILE`) so tests can assert exactly how many real handshakes happened, and honors `MCP_EXIT_NOW` for kill-on-close checks.
  - `ts/plugins/mcp/test/pool-lifecycle.test.ts` (new, 6 tests).
- **Contract invariants satisfied** (C-ADJ-02: 连接按会话/配置指纹隔离、run 结束释放；活动记录只存元数据):
  - Connections are keyed by owner + cwd + config fingerprint; two fingerprints of one server id are two generations — releasing the old lease closes only the old connection and never the newer one.
  - Parallel runs leasing the same server share one connection (one `initialize`); one run ending only drops its reference — the connection stays live for other runs.
  - Run close releases leases: the last release starts the idle grace timer; idle connections close after the grace period and the next acquire opens a new generation.
  - A failed/exited connection retries as a new generation, and the handshake is bounded by the configured connect timeout.
  - Disabling the plugin closes the pool at once: no new connections are created, connecting children are killed, and the runtime port binding is cleared.
  - Activity records carry only counters/ids/versions (generation, toolCount, capability group names) — never tool/resource contents.
