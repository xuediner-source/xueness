# F03.06 Result — Execution Residency & Drain Leases (C-WFL-05)

- **Status**: Completed

## Files changed

- `ts/packages/sessions/src/locks.ts`: `withSessionLease` — the residency-lease primitive mirroring upstream `residency-lease.ts`. It acquires the nonblocking lease once, runs the detached runner's settle window under it, and releases in a `finally`, so normal and abnormal settles both give the lease back. A second writer never waits: `tryAcquire` surfaces `BlockingIOError` (`EAGAIN`) immediately and the caller stays a reader.
- `ts/plugins/workflows/src/dynamic-lifecycle.ts` (new): the explicit cold-resume lifecycle. `DYNAMIC_RUN_LIFECYCLE` is the frozen status graph (`completed`/`failed`/`cancelled` terminal), `transitionAllowed` validates edges, and `coldResumeDecision` maps every at-rest status to exactly one decision: `resume_owner` (a live owner holds the runner lease), `recover_interrupted` (no live owner: acquire and mark interrupted), `await_answer`, `start_queued`, or `settled`.
- `ts/plugins/workflows/src/dynamic-service.ts`:
  - `recover()` now treats the runner lease itself as the owner probe: acquiring it proves no live owner, so a cold `running`/`queued` run is marked `interrupted` (nodes too) via `coldResumeDecision` — never executed alongside a wedged peer. While another host holds the lease, both `recover` and `start` fail with "live owner".
  - `start()` re-checks `#closed` after lease acquisition in the same synchronous section, closing a reproducible race: a start that awaited the owner lookup while `close()` drained would previously register a run the drain had already passed, leaving an orphaned writer. The refused start releases the lease it took, so nothing is left behind.
  - `close()` drains instead of dropping: it aborts and `allSettled`-awaits every in-flight run, then re-checks in a loop until no active runs remain, so a registration that slipped between the closed flag and a snapshot is still settled before close returns. Each engine settles the run on disk under its lease and the lease releases in the done chain.
- `ts/plugins/workflows/src/index.ts`: exports the lifecycle module.
- `ts/apps/server/src/main.ts`: no content change (an incidental mode flip was restored).

## Contract invariants satisfied

- **Leases release on normal and abnormal settles**: `withSessionLease`'s `finally` release covers both paths; the drain test proves the run's runner lease is acquirable immediately after a cancelled settle, and the sequential-abnormal-settles test proves no wedging across repeated failures.
- **Process restart produces no parallel writers**: the runner lease (an OS `flock`) dies with a crashed owner's process; a restart either finds a live owner (`resume_owner` — that host is used, this one stays a reader) or re-acquires the lease and marks the run `interrupted`. Recover-while-leased and start-while-leased are both refused.
- **Runs settle under lease, not dropped**: close aborts and awaits every in-flight run to a settled state on disk before returning; a start that raced close fails cleanly with `workflow host is closed` and leaves no lease.
- **Fixes are tied to reproducible races**: the start/close registration race and the single-pass drain miss are both exercised deterministically in tests.
