# F06.03 Result — MCP Rich Content & Resource Links (C-ADJ-02)

- **Status**: Completed
- **Files changed this round**:
  - `ts/plugins/mcp/src/content.ts` (new): the rich-content projection module. `projectCallContent` / `projectBlocks` walk a `tools/call` (or `prompts/get`) content list: `text` passes through verbatim; `image` blocks and blob `resource` blocks whose base64 decodes and whose magic-byte signature matches the declared MIME become attachments (`McpMedia` with `mimeType` + re-encoded bytes + placeholder, plus the `[Attached <mime>: <placeholder>]` line the agent's tool-media binder consumes); `audio`, non-image blobs, forged signatures, broken base64 and over-budget items degrade to labeled references that keep MIME, decoded byte size and — for resources/links — the source URI, so a large resource can still be loaded by reference through the `_xueness_resources_read` special. `resource_link` blocks project with uri and optional name. One shared budget per result mirrors the agent's tool-media limits (`MCP_MEDIA_MAX_ITEMS = 20`, `MCP_MEDIA_MAX_BYTES = 20 MiB`). `projectResourceContents` gives `resources/read` / `prompts/get` the same projection, returning `null` when everything is plain text so the legacy JSON dump (verbatim source) is kept. Attachment journal metadata (`McpAttachmentMeta`) carries MIME, size, placeholder, source URI and `untrusted: true` — never the bytes.
  - `ts/plugins/mcp/src/client.ts`: `callTool` now runs the result through `projectCallContent` instead of the text-only `callResultText`; `CallOutcome` gains optional `media`/`attachments` that are present only when the result actually carried rich blocks, so plain-text results keep their exact pre-round shape. Error results still map to `toolError` with no media.
  - `ts/plugins/mcp/src/index.ts`: tool results forward `media` + attachment metadata on the `ToolResult` only when present (with the server name in `data`); `_xueness_resources_read` / `_xueness_prompts_read` route rich reads through `projectResourceContents`, attaching blobs as media while plain reads keep the clipped legacy dump; both read specials mark their output `untrusted: true`. Exports the new module surface.
  - `ts/plugins/mcp/test/fake-server.mjs`: `--rich` flag adds a `rich` tool returning all five block kinds (text, PNG image, WAV audio, `resource_link`, embedded PNG resource) plus a blob variant of `resources/read`, with real magic-byte prefixes so signature validation is exercised.
  - `ts/plugins/mcp/test/mcp-content.test.ts` (new, 13 tests).
