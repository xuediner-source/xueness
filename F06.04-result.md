# F06.04 Result — MCP OAuth Discovery & Token Lifecycle (C-ADJ-02)

- **Status**: Completed
- **Files changed this round**:
  - `ts/plugins/mcp/src/oauth-discovery.ts` (new): standard auth discovery and shared token-lifecycle helpers. RFC 9728 Protected Resource Metadata and RFC 8414 AS Metadata are fetched from both well-known generations (path-inserted per RFC 8414 first, then the server-root form the current MCP spec serves), with `wellKnownUrl` exported for URL construction; a protected-resource document that parses but names no authorization servers fails closed, and when no well-known location answers, the server itself is assumed to be its own AS (the spec's compatibility port). RFC 7591 dynamic registration issues a public (no-secret, `token_endpoint_auth_method: none`) client when none is configured; RFC 7009 `revokeToken` is best-effort with every failure suppressed. `mergeOauthConfig` reproduces Python's `oauth_config` semantics (static config wins over the discovery cache, same validation order and refusal messages) without any network I/O, so `oauthBegin`'s Python-parity refusals are unchanged. Endpoint URLs must be https, or plain http only to a loopback host (compatibility port for isolated servers, matching Python's `LOOPBACK`). Documents are capped at 128 KiB, redirects rejected, JSON strictly parsed. Discovery results and any registered credentials persist to `<state>/mcp-oauth/<id>.discovery.json` — mode 0600, symlink-refusing, atomically replaced — i.e. the state dir, never the project package.
  - `ts/plugins/mcp/src/oauth.ts`: `oauthBegin` / `oauthFinish` / `oauthBearer` resolve their configuration through `mergeOauthConfig` (static + cached discovery instead of the old static-only `oauthConfig`); the authorization-code + PKCE flow, 600 s pending state, single-use verifier and locked writes are unchanged. `oauthBearer` refreshes expiring tokens with `grant_type=refresh_token` and preserves the refresh token across rotation; both finish and refresh stamp `revocation_endpoint` into the stored token so a later revoke knows where to go. `oauthRevoke` now performs RFC 7009 best-effort server-side revocation (refresh token preferred, client id included) before clearing the local state file, so no usable session residue survives either way.
  - `ts/plugins/mcp/src/mcp-ops-http.ts`: new `POST /api/mcp/:id/oauth/discover` route (declared in `routes`) returning metadata only — authorization servers, the four endpoints, whether dynamic registration happened and whether a complete static config made discovery a no-op; tokens and client secrets never appear in the response. `revoke` passes the server row so the endpoint can be re-resolved from config/discovery when the stored token lacks one.
  - `ts/plugins/mcp/test/oauth-discovery.test.ts` (new, 7 tests).
