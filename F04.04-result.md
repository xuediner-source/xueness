## Contract Invariants Satisfied (C-SES-04)

- **Replaying the same command never repeats the operation**: the durable claim (commandId + intent payload fingerprint) is written before execution; replays return the recorded acknowledgement (`status: "duplicate"` with `originalStatus`), a reused commandId with a different payload is rejected as `command_id_conflict`, and a claim whose outcome is uncertain (crash between claim and settle) answers 503 `command_unknown` and is never re-executed. Edit retries keep their existing dedup through the durable command-receipt envelope, with lineage rows appended idempotently by `commandId`.
- **New branches preserve correct file/tool context boundaries**: each fork records and returns a `context` receipt — closed-prefix message count, referenced tool calls and results, adopted media refs, and the child-local tool-call id remap — and the child's `results` are keyed by the remapped ids, so tool context crosses the boundary without reusing parent identities. Rewind lineage records the removed message ids so the original prefix keeps a continuous, explicit boundary; media permissions are never copied implicitly (adoption stays explicit via `media.adopt`).
- **Rewind keeps lease + confirmation semantics**: canonical rewinds still run under the session lease with `confirmed: true` and revision CAS; replays append no second `HistoryReset` runtime event and re-run no side effects.
- **One command, one effect, one lineage row**: every executed intent appends exactly one lineage row (`parentId`, `time`, intent-specific fields) queryable via `GET /api/sessions/:id/lineage`.
