# F10.03 — Deepening Typed Actors and Repair

## Summary

F10.03 deepens the typed-actor layer of the dynamic workflow engine in `ts/plugins/workflows`: every ask to a typed actor is schema-validated, transcribed, attributable to one actor node, and repairable within an explicit budget, while settled side effects are replayed — never re-submitted — after a resume.

## Files Changed

- `ts/plugins/workflows/src/dynamic-actors.ts` (new, ~220 lines): the typed-actor module.
  - `defineTypedActor` validates and freezes an actor spec (name, optional persona/input schema, required output schema, repair budget 0..8 with default 0).
  - `classifyThrown` maps failures onto the taxonomy: `aborted` (never repairable), `driver_error` (contract violations), `actor_error` (everything else).
  - `createRepairDriver` wraps a `DynamicWorkflowDriver`: untyped actors pass through untouched; typed actors get output-schema validation per ask, a repair re-ask whose prompt names the offending paths and the previous invalid answer, and a final `ActorRepairError` carrying the full attempt history when the budget is spent.
  - `memoryTranscriptStore` / `ActorTranscriptStore`: per-run, per-node attempt transcripts (`ActorAttempt`: instructions, output, issues, classification) so any invalid result is locatable after the fact.
  - `SideEffectLedger`: at-most-once effect execution keyed by `ask:<runId>:<nodeId>:<inputHash>`; completed values replay, recorded failures replay as throws.
- `ts/plugins/workflows/test/dynamic-actors.test.ts` (new): 16 tests.
- `ts/plugins/workflows/src/index.ts`: re-export `dynamic-actors.ts`.

## Contract Invariants Satisfied

- **Invalid results are attributable to one actor**: `ActorFailure` and `ActorRepairError` carry `actorId`, `nodeId`, `siteId`, `runId`, and the failing `attempt`; the transcript records every attempt's classification and issues.
- **Repair has a budget**: budget 0 fails fast on the first invalid answer; a budget of N allows N repair re-asks and then fails with `budget_exhausted` naming the spent budget; aborts and base-driver failures are never repaired, only classified and rethrown.
- **Resumed runs do not re-submit completed side effects**: a settled ask keyed by run/node/input-hash is replayed from the ledger (value or recorded failure) without invoking the base driver again — verified by a submission counter staying at 1.
