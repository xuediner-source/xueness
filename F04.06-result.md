## Model

`repairSessions(store, { relocations, dryRun })` scans `<state>/<sid>.json`
journals directly (not `store.list()`, which silently skips journals missing
`task`/`status`) and classifies each session as `ok`, `repaired` or
`unrepairable`:

- **Path migration** — a recorded root that no longer exists is mapped
  through `relocations` (`from` → `to`, subdirectory suffixes preserved,
  `realish`-normalized comparison); the target must exist on this machine,
  otherwise the item is reported `missing_workspace: <path> does not exist`.
  A journal with no root at all is `missing_workspace_root` — repair never
  guesses a workspace.
- **Legacy schema** — missing current-schema keys are filled with the
  `store.new` defaults (`results`, `compactions`, `archived_messages`,
  `steps`, `completion`, `todos`, `pending_question`, plus `task`/`status`
  fallbacks); a journal whose `messages` is not a list is
  `unsupported_journal_shape` and left untouched.
- **History cursor** — the `<sid>.history.jsonl` chain is replayed with
  `scan`; `history_revision`/`history_hash` are resynced to the last valid
  record (a cursor-only repair appends no junk revision), or cleared when
  the sidecar is gone so the next save writes a fresh baseline. A chain that
  cannot replay is `history_chain_invalid` — never rewritten, since that
  would destroy the evidence.
- **Publication** — repairs are applied only through `store.save`, so every
  repair is a normal revision and the hash chain continues; nothing else in
  the state directory is read or written.

CLI: `node ts/scripts/session-storage.ts --state DIR repair [--relocate
FROM=TO]... [--dry-run]`.

## Contract invariants satisfied (C-SES-07)

- **Migration keeps execution evidence** — repair rebuilds/fixes only the
  existing JSON journals; it never re-executes old tools and never invents
  roots, hashes or message content.
- **Relocated/upgraded sessions stay locatable** — after a directory move
  the root is rewritten to the existing target and the revision chain
  continues (`reset`-free diff after a cursor resync); legacy journals gain
  the current schema while preserving their content.
- **Unrepairable items report the exact reason** — `missing_workspace`,
  `missing_workspace_root`, `unsupported_journal_shape`,
  `history_chain_invalid`, `unreadable_journal`,
  `repair_publication_failed`, each with the offending detail; the journal
  bytes are left untouched.
- **Migration does not touch local credentials** — only `<sid>.json`
  journals are rewritten; unrelated state files (`credentials.json`, queue,
  media, no fabricated SQLite library) stay byte-identical, and unknown
  journal keys such as `model_auth` survive verbatim.
