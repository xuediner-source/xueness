## 1. Xueness seam (verified local)

- `xueness/provider.py`: `OpenAICompatible` requires `XUENESS_API_BASE` to be an **HTTPS** origin/path with no userinfo/query/fragment; requires `XUENESS_MODEL` + `XUENESS_API_KEY`; POSTs OpenAI-style `{model, messages, tools}` to `{base}/chat/completions`; 2 MB response cap; **all** provider errors suppressed to a generic `RuntimeError` (good: never echoes secrets/URLs).
- `xueness/core.py`: write/exec deny by default; exec is argv-only, 30 s timeout, env strips any var matching `KEY|TOKEN|SECRET|PASSWORD|CREDENTIAL` (so `XUENESS_API_KEY` itself is **not** passed to exec children — by design, note for A2); completion requires evidence citing successful recorded tool-call IDs.
- Consequence: anything behind Xueness must speak **OpenAI-compatible `/chat/completions` with function tool calls** over **HTTPS**, or sit behind a shim that does. Non-OpenAI protocols cannot plug in directly.

## 5. Findings

### Verified (source-read this pass)

- **F1 [High, blocker] Xueness HTTPS-only vs gateway HTTP default.** `provider.py` raises `ValueError` for any non-HTTPS base. The Go gateway default is `http://127.0.0.1:7863/v1` (`DEFAULT_BASE_URL` in `adapter.ts` `82fd4ce7…`; `config.example.json` `19f60037…` listens `:7863`). Direct `XUENESS_API_BASE=http://127.0.0.1:7863/v1` fails before any network call. Integration needs a loopback TLS terminator or a seam change (seam change is out of scope for this audit; adapter A1 describes the no-code path).
- **F2 [High if exposed; deployment default needs verification] Public default shared keys committed in source.** `ZCODE_DEFAULT_API_KEY = 'zcode-e1691d89275a4e7c3c1fedd18a90643c8f37'` (`src/zcode.ts` `0d718b72…`, documented as localhost shared secret); `DEFAULT_API_KEY = 'wb2api-dsh-key'` (`src/adapter.ts` `82fd4ce7…`); `POOL_BASE`/`POOL_KEY` hardcoded to the same key in `docs/xuedinerapi-provider.js` (`0469f12c…`). Do **not** assume loopback binding: `gateway/config.example.json` sets `"listen": ":7863"`, which is commonly all-interface binding. The effective live configuration was not inspected. Any network exposure without replacing these defaults risks unauthorized access. The "zero credentials in repo" README claim overstates by exactly these committed defaults. Bearer auth itself is constant-time via `VerifyBearer` (`httpauth.go` `b1a7fc36…`, verified) and request logs show only uid prefix-8 (`logging.go` `795f2dd9…`, verified).
- **F3 [Medium] `findCommandCodeModel` silently falls back to the first catalog entry on unknown id** (`src/commandcode.ts` `72669d75…`: `return bySuffix ?? COMMANDCODE_MODELS[0]!`). A typo'd `cc/` id routes to `meta/muse-spark-1.3-contributor` instead of erroring. Wrong-model, wrong-billing risk. Gate: unknown id must throw.
- **F4 [Medium] `.credentials.yaml` regex readers with no permission enforcement.** `resolveOpenRouterKey` / `resolveGroqKey` / `resolveLlm7Key` / `resolveZhipuKey` / nine-router + zcode `readCredential` all do `fs.readFileSync` + `^\s*NAME:\s*(.+)$` with no `0o600` check and no YAML parsing (verified in `openrouter.ts` `35b59803…`, `groq.ts` `41bfd2f7…`, `llm7.ts` `8de12056…`, `zhipu.ts` `b4da25c6…`, `nine-router.ts` `7b3cbb22…`, `zcode.ts` `0d718b72…`). Inline trailing comments become part of the value (e.g. `KEY: abc # comment` → `abc # comment`). Contrast subs-hub's claimed `0o700/0o600` store (README + `store-atomic.test.mjs`, production path unread — see U1). Gate: set restrictive perms + strip inline comments or use a YAML parser.
- **F5 [Medium] CodeArts refresh writes back to the credential file with no lock.** `refreshCodeArtsCredential` in `adapter.ts` (`82fd4ce7…`, seen in source excerpt) does `fs.writeFileSync(stored.file, …)` on success; two DSH processes refreshing the same account can clobber each other (last-writer-wins on refresh_token rotation → one side's token dies). No TTL/eviction issue here (refresh is expiry-driven with `REFRESH_LEAD_MS`), but concurrent refresh is unguarded. Gate: single-writer or file lock before enabling multi-account CodeArts behind Xueness.
- **F6 [Medium] usage-board external providers = arbitrary local code exec by design.** `loadExternalProviders` imports every kebab-case `~/.dsh/usage-board/providers/*.js` (`lib/index.js` `973be30d…`); the kebab gate blocks `../` traversal (verified in `detect.js` `validProviderId` + tests) but any file in that dir runs with full Node privileges and receives `{credentials, httpsJson, env, logger}`. Documented extension point, but Xueness must treat that directory as trusted-code-only and check its ownership/perms. Not a bug; a boundary to respect.
- **F7 [Low] usage-board HTTP cache key retains a 24-char auth prefix** (`cacheKey` in `lib/http.js` `cb408914…`: `auth.slice(0, 24)`). In-memory only (45 s TTL), never logged — acceptable, noted for completeness.
- **F8 [Verified good] Loopback plaintext guard is strict.** `isLoopbackUrl` requires an IPv4 literal in 127/8 and explicitly rejects `127.evil.com` (`lib/http.js` `cb408914…` + `test/http.test.mjs` `592b3f58…`, verified). Loopback failures are never retried through a proxy (verified). This is the correct pattern if Xueness ever needs a similar loopback exception — currently it has none (F1).
- **F9 [Verified good] Gateway ships credential-leak gates.** `test/no-secrets.mjs` (`6352ca8f…`) denies `auths/ data/ config.json *.key/*.pem/*.jwk codearts*.json workbuddy-*.json credentials.yaml .env`; `test/contracts.mjs` (`3b08ba08…`) pins upstream-module wiring, retired-MiMo absence, and placeholder `test_key`; `.gitignore` (`612b4fa3…`) covers the same set. The intentional exception is F2's loopback defaults.
- **F10 [Verified good] Qoder ceiling + CommandCode header timeout are pinned in code.** `QODER_MAX_TOKENS_CEILING = 32_768` (`qoder.ts` `f999d6b5…`, measured 2026-09-19 per comment); per-upstream header timeouts 20–120 s; `resolveModel` caps Qoder context at 128K for TTFT (verified in `adapter.ts` excerpt). Xueness `max_chars=24000` default sits far below these — no overflow interaction expected on the seam.

## 6. Viable interface adapters (no code changes, none wired)

- **A1 (recommended first live path): Xueness → public OpenAI-compatible free tier directly.** Set `XUENESS_API_BASE=https://openrouter.ai/api/v1` (or `https://api.groq.com/openai/v1`, `https://api.llm7.io/v1`, `https://open.bigmodel.cn/api/paas/v4`), `XUENESS_MODEL` to one catalog id from `openrouter.ts`/`groq.ts`/`llm7.ts`/`zhipu.ts`, `XUENESS_API_KEY` from the operator's own env. Zero new code, satisfies the HTTPS seam, exercises Xueness tool calls end to end. Priority P0.
- **A2: Xueness → Go gateway `/v1/chat/completions` behind a loopback TLS terminator.** Requires deployment changes (bind gateway to `127.0.0.1:7863` rather than the example's `:7863`, TLS termination on loopback, rotated `api_key`) and verification of actual endpoint behavior, no repo changes: `XUENESS_API_BASE=https://<loopback-tls>/v1`, `XUENESS_MODEL=hy4-preview` (WorkBuddy pool) or `glm-5.3-flash` (ZCode-first rotation). Unlocks subscription quota (CodeArts/Codex/intl) for Xueness. Blocked until F1 (TLS) + F2 (key rotation) + G2 gates pass. Priority P1.
- **A3: Xueness → local 9Router / zcode-proxy.** Same shape as A2 (both OpenAI-compatible) but same HTTPS block (F1) and a public default key (F2, zcode). Lower value than A2 (subset of models). Priority P2, after A2.
- **A4 (not viable without new code): CommandCode / Codex / Qoder / CodeArts direct.** Custom protocols (`/alpha/generate` SSE, Responses API, COSY signing, Huawei HMAC) do not satisfy `OpenAICompatible.complete`. A translating shim would be new code — explicitly out of scope. Do not attempt by pointing Xueness at these endpoints. Priority deferred.
- **A5 (sidecar only): usage-board for quota visibility; subs-hub for login UX.** Neither offers a chat surface. Use the board's `xuedinerapi` external adapter (`docs/xuedinerapi-provider.js` `0469f12c…`, requires copying to `~/.dsh/usage-board/providers/` + rotating `POOL_KEY`) to watch pool/Codex burn while Xueness runs on A1/A2. Priority P1-parallel, read-only.
