# F09.02 Result — 实现有选择的预取与检索 (Selective Prefetch & Recall)

- **Status**: Completed
- **Files changed this round**:
  - `ts/plugins/memory/src/memory-recall.ts` (new, 118 lines): the selective pre-turn recall engine over the F09.01 manifest, exported from the plugin entry alongside the indexer (same engine-module pattern as `memory-dream-*`).
    - `createMemoryRecall(memoryRoot, cwd, limits?)` owns one index per project (`cwd` fixes the KEY track) and answers one question per turn — "which stored memories are relevant to this query?" — without ever putting the whole store into the request.
    - Turn-前 recall: `recall(query)` runs before the turn executes and returns only what the lexical scorer ranks relevant, bounded by the manifest's selection caps (`maxEntries`/`maxChars`, defaults 12/3000). The result is a ready-to-inject block: untrusted preamble + `RECALL_HEADER` + bullets, each closed by its `[<track> #<entry> @<version>]` provenance tag, plus the candidates and the provenance-only manifest; an empty recall is `""` so nothing irrelevant is resident.
    - 语义/索引选择: `relevanceScorer(query)` scores distinct query-term coverage — Unicode letter/number tokens (`tokenize`, `\p{L}\p{N}` runs, case-folded, full-width digits intact), so covering more of the query always outranks repeating one term and no-overlap entries score 0 and are never selected.
    - Incremental refresh: every call stat-probes first (`indexStale`, no body reads) and rebuilds the index only when a track actually changed on disk — `refreshed` reports it; a quiet store never rebuilds (`snapshot()`/`stale()` expose the cached index and the probe for callers).
    - Explicit, non-interrupting fallback: `recall` never throws. When the index cannot be built at all (`ok: false`), it degrades to the whole-track loader (`loadMemory`) with the failure reported verbatim in `result.failure`; a vanished root mid-session still returns `mode: "none"` with the reason. `mode` is `selective` (index hits) / `fallback` (index failed, whole track loaded) / `none` (nothing relevant) — the three states a turn needs to decide what rides along.
  - `ts/plugins/memory/src/index.ts`: re-exports `./memory-recall.ts` (together with the F09.01 indexer).
  - `ts/plugins/memory/test/memory-recall.test.ts` (new, 9 tests).
- **Contract invariants satisfied** (F09.02: 相关记忆可命中；无关记忆不常驻；索引失败回退明确且不中断用户任务):
  - Relevant memories hit: a `docker deploy` query recalls the deploy runbook and the pruning note with descending scores, `[memory #0 @…]` provenance on every hit, while the manifest still summarizes all 5 indexed entries with no bodies.
  - Irrelevant memories non-resident: entries with no query-term overlap (other tracks' preferences, the whole USER/KEY clusters for an unrelated query) never enter the result; a no-match query returns `mode: "none"`, empty text and zero candidates.
  - Explicit fallback, never interrupting: an unbuildable index reports its failure (`ok: false`, reason string) and degrades to the whole-track loader; a root that vanishes mid-session forces a rebuild that fails visibly (`refreshed: true` + failure) yet returns `none` — no code path throws, so an index problem can never break the user's task.
  - Bounded and deterministic: selection caps are honored (`maxEntries` cuts the ranked list, `maxChars` keeps the total body a summary) and identical queries select identical id sequences.
