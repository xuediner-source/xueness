# Qoder 前端报告落实记录（2026-10-04）

本轮基于 `reviews/qoder-frontend-parity-2026-10-04.md`，先核对源码，再实施已确认的问题。保持既定的中性色设计与插件边界，不改变用户状态、模型配置或运行权限。

## 已实现及使用方式

- **设置**：导航上方可以按分类名称、说明或 ID 搜索；匹配到扩展分类时自动展示结果。窄屏搜索时展开导航，显示查询和分类名称；选中分类后清空搜索并恢复图标栏。
- **插件管理**：保留完整 catalog 和禁用/依赖阻塞项；标题与卡片对齐，缩小卡片间距，支持展开/折叠全部子功能。新增功能仍登记在所属插件，不能藏在其它设置页。
- **命令面板**：使用现有搜索快捷键打开，↑/↓ 与 Home/End 选择，Enter 打开；中文输入法组合按键不会触发选择。同名任务显示工作区与更新时间，状态随语言翻译。
- **会话**：跟随最新消息；向上阅读时停止跟随，显示回到底部按钮。运行中的会话刷新采用顺序请求，后台标签页降低频率，恢复可见后及时刷新。仍读取完整事件快照以保证旧事件更新不遗漏。
- **文件改动**：查看带旧/新行号的逐行增删，展开未变上下文。仍来自会话记录，不是磁盘差异，也不提供接受/回滚操作。单侧最多 64,000 字符和 1,200 行，LCS 最多 1,000,000 单元；超过预算会明确提示截断或简化。
- **诊断**：按后端返回的会话状态计数求和；错误形状显示未知而非伪造零。
- **子代理**：供应商插件关闭时不请求模型列表，保留已保存的选择和独立资源管理；丢弃过期/卸载后的结果。
- **基础界面**：明暗主题变量单源；统一状态色、背景、间距、字号、动效和层级令牌；基础次级文本对比度检查。页面头部先读取已缓存主题或系统外观，再由成功加载的设置覆盖。支持跳转主要内容和减少动效。区域渲染失败可重试、重新加载或进入插件管理；资源下载失败使用重新加载，不反复重试 React 已缓存的失败 import；持久会话与配置不会被错误边界修改。
- **启动成本**：语法高亮核心与次级业务面板按需加载；共享 React runtime 使用稳定 chunk 名。保留 `webapp/dist`，直接运行 Python 服务仍有可用界面。

归属：`settings.destination_search`、`sessions.command_palette`、`sessions.timeline_follow` 是新增 catalog 项；逐行差异扩展 `files.changes`；诊断、子代理及主题分别归原插件。局部错误边界、加载占位和设计检查属于既有基础 UI/构建工具，没有新增可执行插件来源。

## 没有盲目采纳的建议

工具详情此前已默认折叠并有工具分组；批准审计也已存在。现有 events.v1 使用 SSE 格式传送有限快照，旧事件可能变化，不能把 seq 直接当成可靠增量游标。四档持久权限与独立拒绝策略需要后端协议设计，不能只画按钮改变权限语义。CLI、工具和自动贡献不必拥有独立页面；完整功能目录仍应可见。

本轮未做全 CSS 的 `@layer` 迁移、长会话 DOM 虚拟化或全面图标重绘；也不宣称满足报告所列 2,500 节点预算。没有移除发布包所需的 dist，没有运行收费/真实模型或修改真实用户状态。

## 维护门禁

`npm --prefix webapp run build` 自动运行插件结构检查与设计检查，再对新构建计算启动 HTML 的静态 JS/CSS 依赖图。预算为 JS gzip 400 KiB、CSS gzip 64 KiB，动态加载资源不计入初次打开预算。文件 gzip 值不是实际网络耗时或 CPU 测量。对比度门禁覆盖基础文本令牌和已登记的纯色表面，不能代替所有组件的视觉/可访问性检查。

## 验证结果

- 前端 **500 项测试通过**；TypeScript 与 Vite 构建通过。
- 插件结构脚本通过；架构和发布归档回归合计 **18 项通过**。本轮没有后端产品行为改动。
- `test:browser` 对 27 份真实 bundled manifest 渲染的插件目录验证原生延迟折叠事件、展开/折叠全部、单卡、搜索强制展开、Enter/Space 与 IME，全部通过；临时目录和服务由脚本清理。
- 系统 Chrome 配合真实 Python 服务和新构建，在全新临时状态/工作区验证：1280px 与 420px、明暗主题、设置搜索、命令面板方向键/Enter/IME、同名任务区分、回到底部、逐行差异与上下文展开、Shiki 代码高亮、会话计数，以及停用供应商后的子代理刷新。普通路径无页面运行错误，420px 无横向页面溢出。
- 在 React 模块被阻止时验证头部缓存主题；在设置请求延迟时验证 React 不提前覆盖缓存主题，响应返回后应用服务端设置。缓存按浏览器 origin 隔离；没有缓存时先采用系统外观。
- 用真实渲染异常验证区域重试、导航恢复与周边界面保留；阻止一个实际构建的诊断插件 chunk 后，确认展示重新加载操作，并仍能进入插件管理。
- 没有复制真实 `.state`，没有调用真实/收费模型、修改用户配置或对外发布。
