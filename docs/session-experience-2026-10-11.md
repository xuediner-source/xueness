# 会话发送、恢复、队列与阅读体验

本轮按本机 ZCode、Codex 和 Claude 解包中的会话交互核对并适配。实现归属于既有 `sessions` 插件，标准和轻量工作台共用同一个 Composer。没有增加共享内核例外，也没有更改用户的模型、权限或实验开关。

## 使用方式

- **发送后继续输入**：提交内容立即移到“正在发送”预览，输入框可继续写下一条。接收确认后移除预览；模型执行随后失败时，不把已接收的消息再次恢复成待发送输入。
- **失败草稿找回**：输入框未改动时，拒绝的消息直接恢复。若已输入新内容，旧消息进入“已保留的消息草稿”，恢复时将现有输入交换保存，附件、上下文引用和目标选项随草稿保留。
- **刷新期间的接收确认**：尚未确认的提交也保存文字和上下文。刷新当前页面后显示“消息接收状态暂时无法确认”，先查看会话与队列再决定是否恢复发送；不会自动重复创建会话或启动模型。
- **附件恢复范围**：当前窗口内保留完整附件。持久草稿不存附件字节；重新打开会提示补充附件，输入文字、上下文选择和待确认状态仍保留。
- **调整排队消息**：使用上移/下移按钮调整尚未领取的消息，Tab 和 Enter 可操作。长消息可展开查看完整正文，队列高度有上限以保留输入空间；编辑继续保留原有准备上下文。已经领取的当前消息不提供编辑、取消和移动按钮。
- **停止与继续**：停止按钮先显示“正在停止”，收到终态后更新。暂停队列通过“继续执行队列”显式恢复；移动或编辑不会隐式启动模型。
- **阅读长会话**：向上滚轮、触摸、PageUp/Home/上箭头会解除贴底跟随。新内容到来只显示“有新内容 · 回到底部”；滚动内部代码块不会错误解除主会话跟随。回到底部尊重系统减少动态效果设置。
- **加载与重连**：首次读取失败后继续恢复，切换窗口或网络恢复时及时同步。运行会话约每秒刷新，空闲会话约每 15 秒刷新，后台不比前台更频繁。断开互联网不会停止本机 loopback 会话同步。

草稿按工作区和会话隔离；切换会话、重挂载输入框以及较晚到达的失败/确认回调都沿用原提交的作用域。草稿持久化仍使用浏览器同源 localStorage；桌面后端重启可能换端口，因此本轮保证的是同一来源内的刷新恢复，不能据此宣称跨端口或整个应用重启后的草稿恢复。禁用 sessions 后不再发起会话轮询或队列操作。

## 接口与持久化

`POST /api/sessions/<sid>/queue` 新增可选 `request_id`，格式为 32 位小写十六进制。正文与准备令牌的摘要绑定该 ID；同 ID、同内容重试返回同一份原始 202 接收回执，同 ID 不同内容返回 409。原始回执和队列项在一次私有原子写入中保存，重试不再次消费一次性准备令牌。

前端仅对队列提交的网络丢失、响应损坏、超时或暂时服务端错误做一次相同 ID 的重放。第一次结果不明后，即使第二次请求被拒绝，也仍提示接收状态不明。CSRF 预检失败属于尚未发送。普通消息和创建会话不自动重放；只把不能确认的提交留作恢复草稿。

回执随有界队列记录保留，当前限制为 20 条活动消息和 40 条历史记录；它不是永久的请求去重账本。20 秒提交截止时间只覆盖接收阶段，不限制已经开始的模型运行时长。读取超时与导航取消共享取消信号，读失败不会吞掉随后切到的新会话请求。

`PATCH /api/sessions/<sid>/queue` 接收 `{ ids, expectedIds }`。两者须是相同集合且没有重复项，`expectedIds` 须匹配最新的可移动列表。调整在同一队列文件锁内验证与落盘；遇到领取、取消、追加或其它重排造成的变化返回 409，并刷新界面。附件与准备上下文不重建、不丢弃；进行中的条目和历史条目位置保持不变。会话载荷增加 `current_queue_item_id` 供界面标记已领取项。

## 验证

后端覆盖回执并发重放、一次性上下文、改写/完成后的原始回执、冲突与插件关闭、存储失败、并发重排和已领取项保护。前端覆盖草稿交换、刷新时的待确认恢复、跨作用域、重挂载后确认、读取取消、断线恢复和本机离线同步。

`node webapp/verify-session-experience.mjs` 启动隔离 Python API 并加载实际 `webapp/dist`，对经典/Claudex × 明/暗 × 1280/420 宽度检查发送失败、边发边写、切换与刷新、长会话滚动、代码块滚动、队列接收回执丢失、重排、编辑、取消、停止与继续。模型运行请求由测试截获；不使用真实服务或付费模型。`XUENESS_SESSION_OUTPUT` 可指定截图和 JSON 报告目录。

Windows 全套后端测试应使用桌面构建环境的 Python（包含 `desktop/requirements-office.txt` 依赖），并将 `TEMP`/`TMP` 指向工作区下的隔离测试目录。系统 Python 缺少 Office 依赖、或临时项目位于被产品拒绝的 AppData 目录时，不能把对应失败当作会话回归或修改权限规则绕过。
