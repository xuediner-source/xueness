# 桌面子代理与主代理并行工作

功能归属：`subagents` 插件。插件面板新增 `subagents.parallel_coordination`，包含后台派发、主代理继续工作、结果收集与完成检查。

## 使用

1. 在「设置 → 插件」确认 `subagents` 及其依赖 `sessions`、`files` 生效。
2. 在「设置 → 子智能体」创建、启用子代理，选择继承主模型或单独的模型配置、推理等级和工具范围。
3. 在运行设置开启「允许子代理」。该开关默认关闭；启用功能插件本身不会自动批准模型调用、写文件或执行命令。
4. 给主模型一个可拆分任务，例如：“委派只读代码审查，你同时检查相关测试；汇总审查结果并自行核验后回答。”

`task` 现在立即返回 `task_id`。主代理随后继续推进能独立完成的工作。`task_collect` 默认不等待，只收集已返回结果；确需等待时，必须提供 `reason=dependency` 或 `reason=no_independent_work`，以及说明具体依赖的 `detail`。每次等待最多 30 秒。派发回执与子代理文字总结不能作为宿主验证证据；主代理应据此检查实际文件、工具结果和交付内容。

宿主不会接受遗漏子代理结果的正常完成回答，会要求主模型继续收集。主模型完成收集后仍需整合结果。失败、取消、尚未完成的子任务会阻止子代理交付检查通过。

这里的“持续工作”指运行调度与可观察的任务推进，无法强制任何模型持续产生内部推理，也不靠无意义请求消耗额度。下一步依赖子代理、独立工作已完成、用户停止/提问/批准、插件关闭、模型服务失败、运行预算耗尽，都可以合理等待或暂停。总步数和用户停止优先于继续工作的要求。

## 边界与恢复

- 单个主任务最多 4 个并发子代理，每个人类轮次最多 8 次派发；进程中尚未退出的子代理请求也占并发名额。
- 子代理保持只读，继承主任务的禁止项与工具允许范围。未知子代理名称报错，不自动退回主模型。
- 子代理最多 4 个模型步骤，使用 120 秒运行预算。内置 OpenAI 兼容及 Anthropic 适配器的普通和流式请求均使用绝对截止时间，重试与慢速数据不能重置预算；更短的继承预算优先。第三方提供者对象仍需自行遵守协作停止与超时协议。
- 主任务结束、暂停、异常、插件关闭或取消时，宿主请求子代理停止；被取消的在途请求在退出前显示「正在取消」。不会继续启动工具或下一次模型请求。
- 子代理的完整对话不会进入主会话；只保留有界结果和进度。恢复时能收集保存的终态结果，未保存完成的在途任务标记中断，不隐式重放。
- 关闭子代理插件后，界面停止请求子代理进度；工作流的独立功能可以继续工作。
