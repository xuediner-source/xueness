# 本机插件适配与 0.2.1 安装状态

2026-10-27 新增 `context_lens`（上下文透镜）：原生适配 dsh-context 0.77.0，默认启用，依赖 sessions/providers。侧栏“上下文透镜”或会话 `/context` 打开面板，设置 → 插件可关闭。它复用上游估算与文件活动算法，接入 Xueness 会话、真实供应商用量及请求生命周期；不需要另装 DeepSeek Harness/Cordis。具体能力、历史记录限制及来源见 [使用说明](xueness-permission-modes.md) 和 [上游对照](../ts/plugins/context_lens/UPSTREAM.md)。

2026-10-24：本机 Windows 已安装版为 Xueness 0.2.1。安装核验显示 33 个插件和 11 项内置技能（原有五项文档/可视化技能，以及用户选择的六项 Seagull 技能）。`native_ops` 与 `batch_calls` 默认启用；WorkBuddy、订阅中心和模型监测为可选插件，新状态默认未安装。启用 WorkBuddy 后，设置页提供号池状态、账号添加或更新、逐账号删除功能。安装与技能核验不代表全部 328 项功能均已逐项实测。

## 初始插件

- **原生操作工具**（`native_ops`）：适配本机 `dsh-ops` 0.4.0 的 Rust 文件与文档工具。默认启用；模型先看到批量读取与发现入口，按会话选择高级工具。支持工作区内读取、搜索、修订校验写入、复制/移动/删除，以及有界 CSV/TSV、DOCX、PDF 文本读取。原生工具不执行模型提供的脚本；Shell 继续使用 Xueness 已有工具。它不加载 DSH profile 或 Cordis 宿主，也不包含其独立 Bash 载荷、PTC JavaScript 执行器和 DSH 专用界面。
- **批量调用**（`batch_calls`）：适配 `dsh-batch-tool-calls` 1.1.2。默认启用，在模型请求中加入独立侦查调用同批执行的约定，并在成功压缩后的请求中恢复提醒。依赖调用和同文件读写按序执行，现有审批与并发上限保持原有含义。

两者均在“设置 → 插件”中显示并支持关闭。原包版本、来源、许可证与适配范围保存在对应插件目录。

## 可选插件

WorkBuddy、订阅中心、返回模型监测均使用可信内置插件清单的按需安装机制。全新状态默认未安装、未启用；先在“插件市场”安装清单，再在“设置 → 插件”中启用。

启用 WorkBuddy 后，在“设置 → WorkBuddy 号池”中：

1. 点击“添加账号”，选择自己导出的单个 `.json` 认证文件。同 UID 再导入会更新认证。
2. 点击“刷新状态”，查看账号额度、冷却状态、在途请求与最近成功/错误；没有上游数据时显示“未报告”或“未知”。
3. 点击某个账号的“删除账号”，再点击行内“确认删除”，即可删除本机认证文件；取消不会删除。

会话模型选择器包含 **GLM-5.3 Flash**（`glm-5.3-flash`），可选择 low、high 或 max 推理档位。该目录来自 2026-10-27 对本机 WorkBuddy 网关 `/v1/models` 的查询；实际请求能否成功仍取决于账号与上游服务。

认证保存在所用状态目录的 `workbuddy/auths` 中，界面与 API 不返回 token。公开构建不携带本机账号种子；源码构建也排除了私有 `assets/auths`。已有本机账号与用户设置没有在本轮准备中被移动或覆盖。
