# 压缩后的任务与技能连续性

本轮从 Claude Code 参考审查中选取“压缩后恢复必要状态”的思路，在 Xueness 既有插件挂接点独立实现。没有导入快照代码、完整提示词或其它工具环境配置。

## 实际行为

- `subagents.context_restore`：每次请求提示当前用户回合仍未收集的真实任务 ID 和最后记录状态，最多 8 项。即使原工具回执离开上下文，也可以收集既有任务而非重复派发。状态可能滞后，模型必须使用 `task_collect` 刷新和收集；提示不包含子任务正文、摘要或错误详情，也不能充当完成证据。
- `skills.context_restore`：通过既有工具事件观察器记录本会话成功的真实技能读取，最多 6 项，只持久化 ID、调用 ID 和回合标记。给模型的提示只包含技能 ID，最多 3000 字符；即使 Unicode 转义变长也保留完整 ID，优先最近读取项。正文不再可见且确实需要时，由模型通过 `skill_read` 读取当前可用版本，不自动重读、不恢复停用资源、不猜测缺失正文。

两个功能在「设置 → 插件 → 已安装功能插件」分别显示在子代理与技能卡片内；完整目录为 28 个插件、162 项功能。没有增加额外设置或后台轮询。关闭所属插件或阻塞依赖后不再向请求贡献提示。新的用户回合不注入旧回合索引；父会话、子代理各自使用自己的会话状态。既有输入预算、Gate、审批、只读子代理限制和结束前收集校验保持生效。

## 验证边界

回归使用隔离状态和确定性供应商，验证真实工具分发、成功与失败读取、停用后重读拒绝、插件／依赖关闭、持久化和压缩恢复、标准与轻量请求、回合隔离、数量与字符预算，以及元数据不会改写工具结果或完成证据。这些测试不代表测量了真实小模型性能、缓存收益或内在推理时长。

供应商最终证据兼容和标准模式按需工具发现不在这两项补强的实现范围内；当前模型若未提交有效引用，仍应保持“未验证／未评估”。
