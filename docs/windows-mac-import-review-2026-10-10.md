## 本机审查修复

- Windows 的 `NtCreateFile` 同步 I/O 增加明确的 SYNCHRONIZE access；错误 NTSTATUS 转成 Win32 错误，保留 ntstatus，避免 unsigned 值引起 OverflowError。原生锁回归验证租约互斥、journal 保存和释放后重新获取。
- Windows 模型停止与总限时直接中断本请求的原始 socket handle；不再保留阻碍阻塞读取退出的额外 Winsock handle。POSIX 继续使用自有副本；SSL 不支持 dup 时使用拥有所有权的原始描述符副本。正常结束仅释放副本，不关闭仍由调用方管理的原始连接。
- Windows 进程树回收的最终兜底使用 Popen.kill，避免引用该平台不存在的 SIGKILL。
- Windows 文本管道先收集字节，再由调用线程按明确编码解码；strict 解码失败不能只在后台线程打印后伪装成成功，UTF-8 replace 和换行行为保持跨平台一致。
- 远程帧的序号分配与写出使用同一输出锁，防止先写并确认 N+1、后写 N 导致断线重放遗漏。
- 输入框增量附件使用当前工作区/会话草稿键，连续选择文件不能绕过已有附件数量和大小预算。浏览器回归覆盖第五个附件被拒绝、前四个保持不变。
- 起始页在工作区根未就绪时暂时禁用发送，避免提交到未确定的工作区。
- 原生 Intel Mac 验证发现工作流结束记录先于 runner 锁释放，立即恢复会撞到尚未退出的旧 owner。结束时先等待执行器退出，在记录锁内提交结果并释放 runner，读者随后才能看到结束状态；回归用受控线程交错验证立即恢复可取得锁。Linux 大小写测试夹具同时显式指定平台，并保留当前原生主机的路径检查。

边界保护、插件开关、一次性审批、完整访问确认及默认关闭的实验开关保持有效。Windows 无法模拟真实 POSIX dir_fd/pathlib 语义的夹具明确跳过，并补充真实 Windows 句柄和路径回归；没有仅靠 mock 平台通过就宣称完成原生适配。
