# Xueness 完整对齐 ZCode：任务清单与阶段交接

日期：2026-10-24。项目版本：**Xueness 0.2.1**。本计划含 **15 个大阶段、82 个小轮次**。F00.01 静态差异盘点已完成；其余轮次是后续工作，已有实现写在“当前基础”栏，不表示这些能力全部从零开发。

## 目标与固定基线

以 [ZCode 最新 main 源码快照 3.16.2](https://github.com/zai-org/ZCode/tree/3c5b227649371507ddc4eb46ac5133afe6db1cab)（commit `3c5b227649371507ddc4eb46ac5133afe6db1cab`）为本期基准。它是源码版本，不声称同名正式发布标签或二进制。旧参考为 3.15.1 / `aac4755666d09fdcd70272fcf063c077a639015f`。上游 CLI 的 contracts/core/adapters/bootstrap/dynamic-workflow 五组 src 在两次参考之间有 249 个文件变化；这不是 249 项功能，也不是覆盖率。

“完全对齐”按公共能力、可观察行为、协议、恢复、错误边界和生产入口验收，不能靠堆积代码或复制空接口宣布完成。保留 Xueness 插件架构；需要线协议兼容的部分提供真实兼容入口。上游官方私有服务相关机制也必须有端口与替代实现；若缺服务接入条件，保留为明确未验收项，不能把它从目标中静默删除。上游新版本在阶段边界重新固定基线并追加差异，不在实现中途追逐浮动 main。

本次审计、分类和优先级由主代理决定；子代理只按确定任务执行。具体代码接线、证据与未证实项见 [完整差异审计](audits/20261024/AUDIT.md)，机器状态表见 [JSON 清单](ZCODE-FULL-ALIGNMENT-TASKS-20261024.json)。

## 当前可交接基础

- 本机桌面端已更新为 0.2.1；33 个插件，11 个 bundled skills，包括用户选择的 6 个 Seagull skills。
- native_ops、batch_calls 是初始启用插件。WorkBuddy、订阅中心、模型监测保持可选；WorkBuddy 设置已有账号状态、添加/更新、删除入口。私有账号保存在用户状态，项目包与仓库不包含账号种子。
- 已有多供应商模型执行、Goal 继续、子代理协调、DAG/动态工作流子集、MCP 基础、空闲任务、会话持久化/回退、文件 CAS、原生 v2 订阅和桌面端。不能将这些全部重新列作缺失。
- Z1–Z8 文档记录前期已交付范围，不是当前最新 ZCode 的全面对齐证明。当前无新的真实模型对照成绩、三平台全量成绩或覆盖率数字。

## 实施顺序和交付规则

先完成 F00，优先推进 F01/F02/F03/F04 的执行闭环；F05/F06/F07 与 F08 可在契约稳定后并行。F09/F10 深化记忆与工作流；F11/F12/F13 完整补齐外部协议和交互/服务能力；F14 统一收口。表中的依赖是阶段约束，不要求所有模块串行等待。

每个小轮次必须交付实际生产接线、插件归属、受影响文档和一项足以证明边界的验证。主代理负责设计、范围和验收；执行子代理用 **GPT-6-Luna / max**。按大阶段汇报，小轮次用于内部推进。只做受影响回归；类型、插件、行数和必要构建按阶段集中检查，集成边界有新风险时再扩大验证；不在每一小轮重复全套。收费模型实测须有相应用户授权。

共享 store/journal/lease/Gate 等按现有共享边界扩展；新增产品能力必须归属插件，登记双语 feature、模块、依赖、工具和前端。保留用户工作区、会话、模型配置与插件开关，使用隔离数据验收。保留已有 Windows Job Object、rename 前 CAS 等有效保障。

每个阶段结束产生：变更与契约映射、最小验证结果、更新后的差异账本、可复现构建/源码清单。验收失败不将状态改为完成；仅有类型或 fixture 通过不能代替真实入口行为。

## 完成判定与交接入口

82 个轮次不是对现有完成度的百分比换算。最终完成必须同时满足：公共能力表无未处理缺口；关键生产链有可复现行为证据；协议兼容有真实客户端/契约测试；升级保留数据；支持平台有实际结果；源码树与完整项目包逐文件校验一致。外部服务条件未满足时，要列出具体端口、可运行替代、缺少的条件和未验收项，不能宣布“完全对齐”。
