# 本地模型轻量模式

在供应商配置或 CLI 使用 `--lightweight` 启用。轻量模式提供精简工具、按需发现、分页结果和有界上下文，适合本地模型工作流。

输入预算由模型上下文容量减去输出与安全预留得到。接口报告有效 usage 后，宿主校准估算；缓存 Token 是输入子集，不重复计入输入总量。缺少 usage 时保留估算，不伪造实际消耗。

未显式提供 `--max-chars` 时使用 Token 预算。明确传入的字符上限继续生效；`--max-tokens`、`--steps` 和 `--max-wall-seconds` 可进一步限定本次运行。实际步骤也受供应商轻量配置约束。

超过预算时，providers 批量裁剪旧交换并保留余量，后续请求复用检查点。人类要求和当前工具交换保留，原始完整记录仍在 journal。需要旧证据时按工具回指读取。

长文件可分段调用文件工具：

```json
{"path":"result.txt","content":"第一段\n"}
{"path":"result.txt","content":"第二段\n","append":true}
```

每次仍需 path 和 content。追加不自动插入分隔符；新文件为 UTF-8，已有文件保留编码与主行尾。建议每段约 4000 字符以降低模型输出截断概率，这是指导而非强制输入上限。

planning 从“交付”“保存”“deliverables”等明确指令登记输出路径，包含代码、测试、数据与报告文件；输入和参考路径不作为交付物。用掉四分之一步骤仍没有任何输出文件时，提示开始保存可复用实现和已有发现。接近预算时提示实际缺项，若最后阶段仍缺文件，再核对一次，整轮最多三次。文件落盘不代表功能验收通过；普通对话不收到工作交付提醒。

在原生工具模式中，如果明确要求的文本报告仍不存在，最后四步内预留一个报告生成步骤，优先保存模型对实际结果、失败与未完成项的说明，然后继续原任务。报告步骤使用独立生成视图，把原任务和近期会话的有界摘录作为事实材料传入，明确标注材料不完整，原会话记录保留；此步骤只选择写文件工具，仍经过当前文件权限与审批。不增加模型请求上限、不覆盖已有报告、不替模型编造 JSON 结果或修复代码。报告生成属于 `planning.report_finish` 功能。JSON 工具协议继续使用普通收尾提醒。

轻量模式由自己的请求窗口管理历史，不叠加旧语义整理。辅助整理的内部超时记录为失败，用户主动停止仍按取消处理。模型仍可能生成错误代码、参数或不完整交付，结束状态和单次工具成功不等同于完整验收。

`planning.failure_repair` 将实际失败的工具输入和错误首尾摘录带入接下来的修复步骤，引导定位原因、修正并重跑原检查；只有原检查实际成功才记录该检查通过。最多保留四个未解决失败，修正中途的工具参数错误不会覆盖原检查失败。文件修改成功后，下一步优先复跑原检查，避免反复按旧错误重写。没有代码变化时，单个失败最多占用四步专用提示，检查耗时文字变化不会重置该窗口。用掉四分之一步骤后，宿主根据实际文件缺项指定下一份交付物。提示同时包含剩余步骤与用时。模型提前结束而仍有缺项时，最多在同一预算内继续两次，不追加轮次或提高请求上限。权限拒绝、等待审批、用户停止和插件关闭不触发自动修复；报告通常避让正在进行的修复，会参考本轮已观察到的最长模型调用耗时提前安排保存机会（基础预留为总时长15%且最多两分钟，不提高原上限）。原始记录与工具权限保留，文件存在及检查退出成功都不代表整题正确。

命令中明确引用已登记交付文件时，作为候选检查持续跟踪并要求原命令复跑。一般读取、探查及工具参数错误提供诊断；后续工具成功会退出该次操作提示，不把它算成原检查通过。这样不会因读取输入时的旧命令错误，反复要求重新修改程序。

修复指导追加到既有系统提示，保留原编码角色、工具和分页说明；普通交付缺项只补充事实，不切换全局角色。
