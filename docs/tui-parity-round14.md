# TUI behavior comparison — round 14

The behavioral reference is the local ZCode v3.15.1 source at commit `aac4755666d09fdcd70272fcf063c077a639015f`, specifically `apps/zcode-cli/packages/tui/src` (91 source files). This comparison groups capabilities by user-visible behavior; it does not claim one-to-one source-file correspondence, pixel-identical output, or the same React / OpenTUI renderer. Xueness renders its own ANSI terminal interface and connects it to the existing session and permission ports.

| Capability group | Xueness terminal behavior in this round | Scope and boundary |
| --- | --- | --- |
| Entry, command and selection menus | Full-screen chat is selected with `chat --tui` on an interactive TTY. Tab menus cover slash commands, models, effort, modes, files, sessions, children and actions. Ctrl+P opens session selection; Ctrl+G and `/tasks` open child selection. | The non-TTY CLI keeps its existing line interface. Session selection is unavailable during an active run. |
| Keyboard, editor and transcript navigation | Multiline editing, bracketed paste, input history, menu navigation, PgUp / PgDn transcript scrolling, Ctrl+Home / Ctrl+End, selection copy, Escape pause and two-press Ctrl+C exit are supported. | Key sequences depend on terminal support; no claim is made that every terminal maps modified Enter identically. |
| Permission and question dialogs | Inline approval shows the exact tool request and offers allow-once, exact project-scoped remember when supplied, or deny; the operator can add denial feedback. Structured questions support multiple prompts, single- or multi-select choices, custom answers, skip and a review step. | Backend gates continue to decide whether an operation requires approval. The TUI does not grant permissions on its own. |
| Queue and current-turn steering | While a turn is running, Enter queues a follow-up; Ctrl+Enter or Ctrl+S submits guidance to the current turn. `/queue` lists pending inputs and can withdraw the selected item. | Delivery and withdrawal use the existing session queue / steering services. |
| Sessions and child timelines | The session picker resumes an existing session. The child picker loads a task transcript as a read-only view; Escape returns to the parent transcript. | Child browsing displays a snapshot and does not add task mutation controls. |
| Transcript cards, Markdown and diffs | Foldable reasoning, tool, compaction and workflow cards show available details. Markdown includes headings, emphasis, code, links with target URLs, quotes, lists, fenced code with basic token coloring, and width-bounded GFM tables. Diff additions, deletions and hunk headers receive distinct colors. | ANSI color and terminal-cell wrapping are implemented independently; rendering is not pixel-identical to a desktop UI. |
| Theme, sidebar and status | `auto`, `light` and `dark` themes use truecolor ANSI palettes; `auto` uses OSC 11 when the terminal replies and otherwise defaults to dark. A 42-column sidebar appears automatically above 120 columns and as a toggled overlay at narrower widths. It shows available status, subagent, MCP, modified-file, todo and actual usage data; APIs are developer-only. | Missing usage or context data stays absent. |
| Clipboard attachments | Ctrl+V reads a PNG image from the system clipboard and stages it as an attachment; selected text can be copied to the system clipboard. | This uses a clipboard PNG attachment path, not an in-terminal image or graphics protocol. macOS and Linux clipboard paths are implemented but have not been physically tested. |

Xueness backend mode names remain `plan`, `build`, `edit` and `yolo`. This round does not implement ZCode's `guarded` mode. The TUI interaction alignment does not migrate account login, billing, branding or telemetry. Source and built Windows ConPTY runs passed with local scripted providers; macOS/Linux terminals and real clipboard operations have not been tested on a device.

Use `node ts/apps/server/src/cli/main.ts chat --root . --tui` from the project root, or `bin/xueness chat --tui` on POSIX. Acceptance commands are `node tools/verify-tui.mjs` and `node tools/verify-tui-queue.mjs`, plus both with `--built` after building. All four passed this round. The harness records an unavailable native PTY exit code as null and independently checks that the CLI main function returned 0 and restored the alternate screen; it never treats an unknown native exit code as zero.
