# 设置、工作区与旧壳移除（第二十四批）

2026-09-30。本批再次检查旧 ZCode 机壳的设置与目录服务，补齐 Xueness 原生工作台对应流程，并准备本地源码发布包。

后续更新：2026-10-01 的[项目选择与会话历史导航](xueness-project-history-2026-10-01.md)已在 macOS 本机连接加入系统目录选择和持久项目登记。本页以下记录第二十四批的历史行为，“增加目录范围需要重启”已不适用于通过系统窗口选中的新项目。

## 设置页面

设置采用独立分类侧栏、搜索、标题说明和明确的未保存状态。原版 Web 设置显示 13 个分类；Xueness 按自身插件能力组织 19 个分类，包括通用、工作区、外观、快捷键、浏览器、模型、Agent、MCP、技能、命令、子代理、Hooks、记忆、插件、扩展、远程、自动化、用量和诊断。禁用的插件不会继续调用对应设置资源；插件管理入口始终保留。

通用页支持语言、自动滚动、任务待办、工具详情折叠，以及探索、终端和文件修改的连续工具分组。分组保留事件顺序和每个调用的成功/失败信息。外观页支持主题、界面字号、Tab 宽度、文件预览换行和交互终端字号；终端字号调整不会创建新 shell。快捷键支持新建任务、命令面板以及 Enter/Mod+Enter 发送。Shift+Enter 始终换行；中文输入法组合状态不会发送。

浏览器开关作为新任务的默认值，在开始界面仍能单独切换。MCP、子代理和 Hooks 默认关闭；读取失败时不会隐式开启。模型、资源、插件、远程连接和自动化使用各自真实 API 与编辑控件。

保存保留同一分区的未知键，传播读取/写入失败，并用服务器落盘数据核验结果；不会把默认值当成写成功的证据。后端对设置分区与工作区偏好使用共享的原子 read-modify-write，防止不同分区的并发保存互相覆盖。

## 工作区流程

“设置 → 工作区”提供完整路径输入、浏览、范围根目录、面包屑、上一级、新建子文件夹、最近目录和保存默认目录。开始界面的“打开文件夹…”提供独立选择流程，只有点击“使用此文件夹”且主机验证成功后才切换新任务目录；取消会保留原选择。

默认目录只影响后续新任务，不移动文件、不更改已有会话或运行中的任务。最近目录去重并最多保留 10 项，已不存在、越界或无效目录会被过滤；自动生成的独立会话目录不会污染最近项目列表。

主机批准的范围包括项目目录、独立任务目录与显式配置的项目根。浏览器的路径提示只是预检，服务器会再次规范化路径并检查目录范围、文件类型与写权限。不能通过保存默认目录扩大宿主允许范围。

```sh
python3 -m xueness.web --port 8138
# 额外批准一个已存在的项目根；可以重复指定
python3 -m xueness.web --port 8138 --workspace-root /absolute/path/to/project
```

需要增加范围时重启服务并使用 `--workspace-root`，或使用既有宿主环境根配置。相对路径、普通文件、不存在的目录和整个 `/`、`/tmp` 根不能成为默认工作区。macOS `/var` 与 `/private/var` 等路径别名由服务器规范化处理。

## 对照与移除范围

历史本地机壳固定在 ZCode `328c1a0c0ffaa5a4f65e8fa199af5e4c20706e5f`；上一批已核对 v3.14.3 `29628c9acdb81b703bbd4080c207a0e7ce5e276e` 的开始界面操作。旧机壳的 `supportsSettings=false` 不会隐藏设置页，因此本批实际检查了设置服务的读写链。

旧壳模型配置更新只重新读取；文件服务仅目录浏览真实接线，文件读写与高级编辑器没有完整接线。数据库迁移、桌面 IPC、云账号同步与运行偏好同步是占位实现。代理、终端配置和部分自动归档字段虽能保存，却未由 Xueness 的 Python provider、终端或 task service 消费。原生设置只展示本项目实际有作用的选项。

已移除 `vendor/`、`webapp/src/legacy/`、旧适配器/快照/注册表/浮动控件、旧快照验证器、Material Icons 和未使用的单文件静态机壳。入口、Vite/TypeScript 配置、依赖锁文件、旧切换命令和静态路由同时清理。自有事件/帧 golden 校验继续保留；Apache 归属、历史来源和当前生产依赖的许可证通知继续保留。

本批不声称复刻上游所有平台能力。原生桌面控制、云账号与商业额度、服务端聊天输入队列，以及第三方插件 ABI 仍不属于当前 Web 实现。没有推理事件内容时不会提供虚假的推理显示开关。

## 发布与验证

使用 `tools/prepare_release.py` 创建本地 0.1.0 源码归档、逐文件 manifest 和 SHA-256 校验。包内包括预构建 Web，运行后端无需 Node.js；重建前端才需要安装 npm 依赖。归档排除本地状态、凭据、Git、依赖安装、截图与旧机壳。详见 [本地发布准备](release-preparation.md)。本批没有远程发布、创建 tag 或推送。

已完成全新 `npm ci --offline` 后的 TypeScript 检查、264 项前端测试、生产构建与自有事件/帧 golden 校验；构建只剩 PPTX 预览器的大分包体积提示。退役机壳检查扫描了 92 个原生源文件与 8 个构建资产，没有旧壳/vendor 引用。

隔离浏览器完成 19 个设置分类导航、设置保存与刷新回读、创建文件夹、输入路径浏览、上级导航、保存默认目录、最近目录、开始页取消与确认选择、Mod+Enter 实际发送及新任务使用默认目录。现有会话目录未被改变。中英文、浅色/深色、320px 与 390px 布局均检查，没有页面异常、请求失败或外部网络请求。

用户提供的本机 WorkBuddy API 实时发现 16 个模型，并用 `deepseek-v4.1-flash`、`low` 推理完成真实 read 工具调用与多轮结果回填。第一次模型使用 Markdown 和错误证据字段，Xueness 保持严格校验并标记 `needs_review`；明确格式后的同一会话得到 `completed` 与 `completion.verified=true`。共 3 个模型步骤、8364 个标准用量 token，没有文件修改。测试配置与密钥仅在隔离临时环境中使用，保存的测试模型配置随后已删除。

后端全量测试：1026 项，1004 项通过、22 项跳过（平台/可选集成及重复 HTTP fixture）。本地源码包的 SHA-256、逐文件 manifest、标准库隔离解释器启动、静态资源、插件、默认目录、会话持久化和抽取后的打包测试均已验证。
