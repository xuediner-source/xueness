# 自动化界面与首次启动权限引导

本轮在 5de5635 基线上继续开发；验收只使用临时状态目录。不会改写真实会话、工作区、模型配置或插件开关。

## 自动化与市场

自动化的计划概览、下次运行、审批状态和主要操作统一层级；闲时任务清楚区分窗口时间、排队状态及历史。明暗主题、窄屏、确认弹窗和输入法键盘行为保留。界面变化不会批准计划或启动模型。

扩展市场的样式与展示结构已整理为可重建的源码，并移除头部绿色渐变装饰；后端接口、安装确认及可信清单边界保持原行为。

## 权限引导使用方式

桌面版第一次打开且 `onboarding` 与 `desktop` 插件生效时，显示三个可跳过的步骤：

1. 辅助功能及屏幕录制：显示系统查询的实际状态；点按钮后才请求辅助功能，或打开固定的系统设置页面。
2. 完全磁盘访问：进入系统设置，由用户自行添加或选择 Xueness。**没有可靠的公开接口可验证授权，本项始终说明需要在系统设置确认。** 不探测个人文件来猜测权限。
3. 麦克风：点击允许后才调用系统授权接口；引导不开始录音。

全部跳过或完成最后一步会将 `{completed:true,version:1}` 原子保存到当前状态目录的 `desktop-onboarding.json`，权限本身仍由操作系统保存。重装应用不会清除进度，换独立状态目录则重新引导。`设置 → 关于 → 查看权限引导` 可重新打开并刷新状态。系统设置变更可能需要重新打开应用。

这些权限是可选的准备步骤；当前引导不实现电脑控制或语音转写，也不把系统授权等同于工具审批。文件操作仍遵守工作区边界、Gate 和原有批准策略。浏览器普通 Web 页面不请求本机系统授权；不支持的平台显示实际的不支持状态。

### 授权后的状态刷新

修复系统设置中开启授权后，引导页仍显示旧状态的问题：引导打开且可见时，每次状态读取完成后等待 2 秒再查询；回到窗口、页面重新可见及手动刷新会及时读取。请求串行，隐藏、关闭引导或禁用所属插件后取消请求和定时器。授权操作及进度保存期间暂停后台检测，避免旧查询覆盖新的授权结果。

“已允许”只根据原生系统查询显示，不因点击设置按钮推断授权成功。macOS 仍报告屏幕权限未生效时，页面提示先刷新，若已在系统设置开启但仍未生效则重新打开应用；不自动重启或代用户授予权限。完全磁盘访问仍需要用户在系统设置手动确认。

## 插件归属与安全边界

- `onboarding.desktop_permissions`：前端三步引导、首次完成进度、重新打开和插件生命周期；HTTP 家族 `/api/onboarding`。
- `desktop.permissions`：真实状态查询、固定原生授权动作；HTTP 家族 `/api/desktop`。Electron 实现在 `desktop/src/permissions.cjs`，Python 实现在 `xueness/bundled_plugins/desktop/permissions.py`。
- 容器仅按两个插件的 `effective` 状态挂载；关闭任一插件不发起新请求。原生动作再次查询可信宿主的开关，禁用的 403 按拒绝处理。
- 请求通过已有桌面私有 token、Host/Origin/CSRF 校验及私有父子进程桥。动作和权限 ID 是固定 allowlist，不能指定任意 URL、路径或系统命令；普通渲染器仍拒绝录屏、麦克风等权限请求。
- 模型初次配置向导仍属于 onboarding，并保留 providers 依赖；原有 CLI 行为不变。

说明依据：[Electron systemPreferences](https://www.electronjs.org/docs/latest/api/system-preferences)、[Apple 完全磁盘访问](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)、[Apple 屏幕录制设置](https://support.apple.com/guide/mac-help/control-access-screen-system-audio-recording-mchld6aa7d23/mac)。

API 客户端仅增加已有写操作的可选 AbortSignal：取消 CSRF 获取后不再发送后续 POST，属于原有共享请求基础设施；引导自身负责生命周期与具体业务，未新增共享例外。
