# Agent 工作规则（2026-10-07）

## 归属与使用

新增能力 `planning.work_policy` 归属「计划与问答」插件，在「设置 → 插件 → 已安装功能插件」卡片中可搜索“持续执行”或 `planning.work_policy`。完整目录为 **28 个插件、163 项功能**。无需新增设置；启用 planning 时，通过原有 `completion_instructions` 在每次模型请求注入，关闭 planning 后下一次请求不再注入。

标准模式要求明确输出和完成条件、按需拆解任务、先观察再修改、持续执行并收集子任务结果、按实际错误调整方法，以及结束前逐项检查交付。闲聊和用户提供文本的转换直接回答，简单动作不强制写计划。轻量模式使用更短版本，保留单次工具调用顺序，参与原有输入预算；不会自动增加上下文窗口或输出额度。

规则由 `xueness/bundled_plugins/planning/work_policy.py` 提供，使用固定文本，不拼接工具输出或用户任务。它不调用模型或工具，不自动建立目标，不保存提示词副本，不修改供应商、推理强度、插件开关或完成状态。现有交付清单和目标提醒继续注入；工具执行证据及交付内容仍分别由宿主检查。

## 参考范围

工作方式参考官方 [Claude Code 工作循环](https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop) 中的观察、执行、验证，以及前次[快照和提示词审查](claude-code-reference-review-2026-10-07.md)得到的任务管理和上下文思路。文本按 Xueness 现有工具与插件机制重新编写，没有导入上游完整提示词、工具定义或源码。

依用户要求，本次不借鉴安全审查、用途分类或拒绝策略提示词。Xueness 原有 Gate、审批、工作区边界、只读子代理和完成证据校验保持原样。不会用延迟或虚构思考过程制造“思考更久”的外观，也不声称提示词能强制模型内部推理或保证任意任务完成。

## 跨平台与验证

Mac 与 Windows 使用相同规划插件和标准／轻量规则；原生安装器沿用共享版本 0.1.5。两个 CI 流程均纳入 `tests.test_agent_work_policy`，验证实际请求注入、运行中禁用后的下一次请求、轻量预算、既有目标／报告规则保留、计划模式不能写入，以及工具成功不能覆盖缺失交付。验收使用隔离数据和确定性测试提供者，不发送收费模型请求，不当作真实模型性能评测。

本机 Mac 构建与 Windows 原生 CI 结果分别记录；Mac 通过不代表 Windows 已通过。最终交付说明以实际检查和 GitHub 构建记录为准。
