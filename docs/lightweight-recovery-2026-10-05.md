## 修改

- 传递非流式与 SSE 的真实结束原因；保留缓存和思考 Token 细分，缺失计数不伪造。截断、过滤、未知结束原因不能标记为完成。`length` 的原因结合实际用量和已配置窗口判断，无法区分时明确保留生成限制。
- 截断后保留可解码正文，暂停且不验证交付；截断工具调用不进入 journal 意图或执行。不会把截断 JSON 当作协议修复任务反复请求。
- 所有用户补充要求逐字保留，旧工具记录以有界摘录和完整结果引用移出请求；没有额外模型总结请求。系统提示不随历史裁剪重写，工具顺序稳定。
- 最近八次真实输入用量只校准低估，倍率不低于基线。缓存命中的输入照常占上下文；不同模型/路由不共用校准。重试、修复和恢复请求继续预留输出及安全预算。
- 上下文容量不足后，用户续写的首次请求先缩小预算；普通响应后解除恢复标志。搜索预览保留标题、URL、摘录和来源核验状态，相同 URL 在预览内去重，全文仍可分页读取。
- 完成事件增加可选 `incomplete` 状态，界面显示“回答尚未完成 / 已暂停”，校准结果仍标为估算。
