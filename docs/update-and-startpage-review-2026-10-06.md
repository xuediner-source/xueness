# 2026-10-06 起始页与更新复核

本轮由项目所有者的两张截图触发：起始页的大卡片过重，Mac 0.1.2 检查到 0.1.3 后下载报 `Redirect was cancelled`。另确认 Windows 0.1.1 的问题是下载缓慢，并未提供错误或失败记录。

## 已修复

- `sessions.start_page` 使用紧凑快捷按钮，最近项目、会话以无大块背景的列表呈现。原回调、键盘行为、英文词典和插件生效约束保留。
- `updates.desktop` 的 Mac 下载通过 Electron `net.request` 完成，每次跳转先检查固定 HTTPS/主机/端口白名单，再同步继续跳转。保留 Chromium 系统代理、背压、取消、文件大小限制和 SHA-256 校验，拒绝目标不接收请求。
- 所有平台更新设置页显示真实网络传输字节、速度及估算剩余时间。未知数值不虚构；实际报告的 0 B/s 可以显示，剩余时间保持未知。差量更新的传输总量代表网络下载计划，并非最终安装器文件大小。
- 状态退出下载阶段、取消、禁用、完成或晚到的旧事件不会重新显示旧的速度和剩余时间。

## 验证边界

使用临时目录和随机 loopback 端口，没有请求模型或读取用户模型密钥。

起始页验证实际 `webapp/dist`：空/有数据、亮/暗、1440×960/420×960 共八种组合无横向溢出或页面异常；有数据测试只替换 GET 响应，三项目和最多五会话为明确的界面 fixture。列表在工作台内部滚动。

真实 Electron 44.5.1 复现了旧 `net.fetch` 的手动重定向错误。修复后实际 GitHub 0.1.3 arm64 DMG 完整下载 150963223 字节，SHA-256 为 `ad9235f4259c8f61f25c547c95c4376a6f74861a460887bf680fe08f504b83de`，下载后再次校验通过。该检查不运行安装器。

真实 Electron loopback 回归验证：可信目标收到两次请求，禁止跳转目标零请求，256 KiB 文件在服务器完成前开始流式读取；取消使客户端 body 失败并关闭服务器连接。三平台原生构建均运行此回归。

Mac 上通过真实 NSISUpdater / ElectronHttpExecutor 验证 GitHub Windows 公共更新源及完整安装器下载，文件 127128057 字节，electron-updater 内置 SHA-512 校验通过。此测试的 Windows 平台与旧版本是隔离 adapter fixture，不能宣称是 Windows 原生安装验收或用户机器速度。Windows CI 运行同一公共下载检查，再另做隔离 loopback 的真实 NSIS 安装、升级、重启和数据保留验证。完整包可能受 GitHub 线路影响；尚未确定用户 Windows 机器缓慢的具体网络原因。

之前 0.1.3 的更新源检查未覆盖 Electron 实际 DMG 下载，本次补上真实下载与逐跳回归。受此错误影响的旧 Mac 客户端无法靠其损坏的下载器取得修复，需要替换一次应用；替换不修改应用数据。
