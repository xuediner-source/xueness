# 会话对话体验

Xueness 会话工作台支持按轮次继续对话。每轮保留用户消息、助手 Markdown 答复、工具活动和会话终态；普通聊天只显示一次助手答复，终态显示为简洁状态行。没有工具验证要求的普通聊天显示“已完成”，不会伪装成工具证据失败。工具和交付验证状态分别呈现，真实未通过或协议错误时仍可展开查看详情；无需交付清单的普通聊天保留一个轻量清单编辑入口。

助手流式文本和思考增量会随会话刷新显示，已收到的内容在中断后继续保留。工作台只在会话记录明确标记轻量 JSON 工具模式时解码旧版原始协议流；模式元数据抵达前，已识别的协议前缀会暂以“正在生成回复”代替。服务端标记为 Markdown 的新流和原生 JSON 答复会按普通消息显示。协议完成后，助手消息负责承载答复，完成事件用于补充状态；匹配当前轮次的重复总结会折叠。推理默认收起，工具参数和结果也默认收起；工具可按探索、终端操作、文件修改分组，展开后仍可查看完整的已记录输入、结果和错误。待批准操作与待回答问题保留独立卡片和原有操作入口。

运行中的会话可以继续输入并把后续消息加入 FIFO 队列。每项会显示位置和状态，暂停时会显示暂停原因；尚未被 worker 领取的 queued 或 paused 项可单独取消。若领取与取消同时发生，服务端以 409 拒绝取消，工作台刷新队列和时间线显示实际状态。队列沿用当前运行的模型、远程目标、权限和插件上下文。停止运行、等待批准或问题、暂停及运行错误会暂停队列消费；会话停止后只要仍有 paused 队列项，队列就提供明确的“继续执行队列”操作。队列项以独立 ID 记录，刷新页面后仍从会话详情恢复。

长运行状态和停止状态按会话记录。发起或重试一个会话的运行期间，用户仍可切换到其他会话或开始新任务；切回原会话时，工作台继续查看该会话的状态。

输入框遵守现有发送快捷键：Enter 可发送，Shift+Enter 换行；将快捷键改为修饰键模式时，Enter 换行、⌘/Ctrl+Enter 发送。运行期间发送动作变为排队。输入法组合期间 Enter 不会提交。Escape 仍可停止当前会话运行，Stop 控件在排队或输入不可用时仍单独显示。停止后可以直接继续追问。时间线默认跟随最新消息；用户滚动到较早内容后不会被新增流式内容强制拉回，重新滚到底部后恢复跟随。

一般编程解释与文字代码示例不因出现「实现、调试、重构」就要求工具证据；针对工作区、文件或联网状态的任务仍要求证据。JSON 工具协议可省略空 `evidence`，提供商解码边界会补为 `[]`；普通 JSON 内容仍按原文保留。协议中的未配对 Unicode surrogate 会作为格式错误进入有界修复，在写入会话或执行工具前被拒绝，避免保存失败后遗留「运行中」状态。

附件、文件/会话/插件/技能上下文和命令继续由会话 Composer 提交，队列通过一次性预备令牌保存已预备的消息内容。会话消息队列只作用于当前会话；更改中的模型或远程目标与运行上下文不一致时，服务端会拒绝排队并保留输入草稿。队列不改变模型设置、插件权限或运行能力。

这些交互让会话更接近连续协作式聊天，但实际能力仍由当前模型、已启用插件、权限和服务端工具决定，不代表与 Codex 的模型或工具功能完全相同。

本次会话体验改动未直接读取 ZCode 上游会话源码；设计依据是项目已有的上游审查记录和用户指定的 Codex 式简洁会话目标，不声称像素级复刻或完全一致。

本次实现的回归检查使用 SSR 组件输出、事件与 API 数据层 fixtures，以及 TypeScript 类型检查；没有进行浏览器或桌面视觉验收。
