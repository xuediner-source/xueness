# 会话对话体验

Xueness 会话工作台支持按轮次继续对话。每轮保留用户消息、助手 Markdown 答复、工具活动和会话终态；普通聊天只显示一次助手答复，终态显示为简洁状态行。没有工具验证要求的普通聊天显示“已完成”，不会伪装成工具证据失败。工具和交付验证状态分别呈现，真实未通过或协议错误时仍可展开查看详情；无需交付清单的普通聊天保留一个轻量清单编辑入口。

助手流式文本和思考增量会随会话刷新显示，已收到的内容在中断后继续保留。工作台只在会话记录明确标记轻量 JSON 工具模式时解码旧版原始协议流；模式元数据抵达前，已识别的协议前缀会暂以“正在生成回复”代替。服务端标记为 Markdown 的新流和原生 JSON 答复会按普通消息显示。协议完成后，助手消息负责承载答复，完成事件用于补充状态；匹配当前轮次的重复总结会折叠。推理默认收起，工具参数和结果也默认收起；工具可按探索、终端操作、文件修改分组，展开后仍可查看完整的已记录输入、结果和错误。待批准操作与待回答问题保留独立卡片和原有操作入口。

运行中的会话可以继续输入并把后续消息加入 FIFO 队列。每项会显示位置和状态，暂停时会显示暂停原因；尚未被 worker 领取的 queued 或 paused 项可单独取消。若领取与取消同时发生，服务端以 409 拒绝取消，工作台刷新队列和时间线显示实际状态。队列沿用当前运行的模型、远程目标、权限和插件上下文。停止运行、等待批准或问题、暂停及运行错误会暂停队列消费；会话停止后只要仍有 paused 队列项，队列就提供明确的“继续执行队列”操作。队列项以独立 ID 记录，刷新页面后仍从会话详情恢复。

长运行状态和停止状态按会话记录。发起或重试一个会话的运行期间，用户仍可切换到其他会话或开始新任务；切回原会话时，工作台继续查看该会话的状态。

输入框遵守现有发送快捷键：Enter 可发送，Shift+Enter 换行；将快捷键改为修饰键模式时，Enter 换行、⌘/Ctrl+Enter 发送。运行期间发送动作变为排队。输入法组合期间 Enter 不会提交。Escape 仍可停止当前会话运行，Stop 控件在排队或输入不可用时仍单独显示。停止后可以直接继续追问。时间线默认跟随最新消息；用户滚动到较早内容后不会被新增流式内容强制拉回，重新滚到底部后恢复跟随。

一般编程解释与文字代码示例不因出现「实现、调试、重构」就要求工具证据；针对工作区、文件或联网状态的任务仍要求证据。JSON 工具协议可省略空 `evidence`，提供商解码边界会补为 `[]`；普通 JSON 内容仍按原文保留。协议中的未配对 Unicode surrogate 会作为格式错误进入有界修复，在写入会话或执行工具前被拒绝，避免保存失败后遗留「运行中」状态。

附件、文件/会话/插件/技能上下文和命令继续由会话 Composer 提交，队列通过一次性预备令牌保存已预备的消息内容。会话消息队列只作用于当前会话；更改中的模型或远程目标与运行上下文不一致时，服务端会拒绝排队并保留输入草稿。队列不改变模型设置、插件权限或运行能力。

会话可以设一条持续生效的目标：开始新任务时在 Composer 的「+」菜单选择「添加为目标」（输入 `goal` 也会给出同一建议），该条输入会成为本会话目标并在标题下方显示为一行徽标，点击可展开查看完整文本、最近变更记录和「清除目标」；清除后徽标消失，历史仍保留在会话记录里。目标每轮都会以一段不超过 600 字的短提示注入模型（文本过长时截断），因此用户不必反复重申。运行结束时主机核对目标：回答没有明确说明目标是否达成，会话进入需要复核的状态并提示补充结论；明确写出「目标已完成」/“Goal achieved” 才把目标标记为已达成。核对是确定性的规则判断，不额外调用模型，也不会替用户证明目标真的完成——声明达成但实际未完成仍需要用户自行清除或继续。目标归属规划插件：插件关闭时不注入、不核对，「+」菜单不再提供「添加为目标」、徽标消失，CLI 与接口入口一并拒绝。CLI 可用 `./bin/xueness run|chat … --target "<目标>" [--target-replace]` 设置，已有目标时必须显式 `--target-replace` 才会覆盖；`./bin/xueness goal --session <会话ID> [show|set <文本>|replace <文本>|clear]` 查看、设置、替换或清除。会话正在运行时不能修改目标。

这些交互让会话更接近连续协作式聊天，但实际能力仍由当前模型、已启用插件、权限和服务端工具决定，不代表与 Codex 的模型或工具功能完全相同。

本次会话体验改动未直接读取 ZCode 上游会话源码；设计依据是项目已有的上游审查记录和用户指定的 Codex 式简洁会话目标，不声称像素级复刻或完全一致。

本次实现的回归检查使用 SSR 组件输出、事件与 API 数据层 fixtures，以及 TypeScript 类型检查；会话目标另以隔离状态目录和本地假 provider/HTTP 覆盖开关、权限、替换确认与生命周期。没有进行浏览器或桌面视觉验收。

## 前端细节优化（2026-11，Round 1）

本轮沿用 sessions 插件的会话、输入区和起始页能力，以及共享 Shell 的布局与无障碍基础设施；不新增插件能力或改变服务端协议。允许动效时，消息首次出现轻微淡入、工作摘要和推理内容展开过渡，流式正文末尾显示光标。排队控件显示明确文字，停止控件保持独立；停止后仍保留收到的内容。回到底部按钮增加底部留白。减少动态效果设置下，新增位移动效关闭，光标保持静止。

侧栏收放保留宽度设置（默认 270px），窄屏抽屉关闭后不可聚焦，Escape 与焦点恢复沿用原逻辑。两套外观的空态使用相同间距节奏，保留真实入口。原生 details 内容高度过渡依赖浏览器的 `interpolate-size` / `::details-content` 支持；旧浏览器保留原生展开行为。

## 前端细节优化（2026-11，Round 2）

归属仍为 sessions 插件的时间线、Composer 与起始页，以及 planning 插件的会话目标；没有新增服务端能力。历史消息以短促的 2px 入场落定，live 答案仅柔和淡入；按会话/行键去重，并用 `data-entered` 标记已入场节点。流式答案沿用根节点光标，答案下方预留状态行持续显示状态文字与轻微扫光，停止后保留正文。减少动态效果时入场和扫光关闭，状态文字静态显示。

发送为圆形，排队为对角圆角的描边轮廓，停止为小圆角方形；均保留原尺寸、可访问名称与快捷键，排队仍为图标按钮。回到底部控件由 sessions 的 `useTailDockClearance` 测量当前 pane 的 composer/queue dock 与视口交叠，仅补偿实际遮挡：已经在视口外占位的 dock 不重复增加偏移。托盘增长时立即让位，收起时允许轻缓回落；卸载释放观察器。

Claudex 空态缩短 greeting、composer、操作与最近列表的间距，短屏从顶部排列；经典外观保留原有较舒展节奏。planning 的目标栏默认以紧凑文字元数据显示，展开后保留边界、历史和全部操作。以上是在既有设计语汇内增加状态辨识与空间利用，不代表已证实超过商业桌面产品的整体体验。

## 前端细节优化（2026-11，Round 3）

归属继续沿用 sessions 的时间线、查找与 Composer，以及 planning 的会话目标；没有新增能力、模块或服务端契约，现有插件目录登记不变。流式答案根节点始终预留 8px 底边，光标和一条静态渐淡细线绝对定位于该边，避免由 Markdown 最后一个子块决定光标位置，也避免结束时撤销光标改变高度。细线不叠加第二套扫光，减少动态效果时光标保持静态，中断后的正文仍由原有逻辑保留。

回到底部按钮继续避让当前 pane 内的 sticky 重叠；视口下方紧邻的 composer/queue 栈按矩形并集计算，对超过 96px 的高度取六分之一作为额外留白，上限 32px 且不超过视口高度的 12%。这不是再次补偿整个托盘高度；普通 dock 留在原 token 下限附近，托盘增高时适度抬升，收起沿用缓降。观察器清理、点击恢复跟随和快捷键不变。

经典时间线顶部留白由 56px 收至 44px，行间及工作区间距由 20px 收至 16px；Claudex 保持 24px 顶部留白。目标栏缩紧元数据内边距，状态只用文字字重和语义色区分，展开及暂停/继续/清除入口不变。≤360px 查找栏采用普通文档流并让输入框优先收缩，经典外观取消横向偏移，避免查找控件悬浮盖住消息操作。Claudex 停止按钮悬停采用独立混色填充，保留方形、焦点环和禁用状态。

这些调整旨在超过仅有状态 shimmer 和原始 ZCode 间距的基线：答案本身表达流式存在感、托盘留白响应实际高度、经典正文层级更紧凑，纸感停止按钮同时提供形状与填充反馈。整体体验是否达到用户指定的 above-floor 标准仍须实际流式与多 pane 视觉复核；不以静态样式检查代替真实模型、队列增长或虚拟化验收。按钮退出淡出暂缓，避免引入额外挂载生命周期。

## 前端细节优化（2026-11，Round 4）

归属沿用 sessions 的侧栏、Composer、起始页和视图导航；共享 Shell 与 Select 只负责布局和可访问交互，不增加产品能力，现有插件目录登记不变。Claudex 收起侧栏时保留隐藏 aside 的网格占位，主区继续落在可伸缩的第二列；窄屏侧栏沿用固定定位、inert、遮罩与焦点恢复。

禁用发送使用可读的中性轮廓，配置模型提示与链接保持清晰字重；≤480px 工具栏明确分为辅助/权限与模型/用量两行，发送对齐底行。空态从顶部有界留白开始，Claudex 比经典更紧凑；移除建议卡片重复上边距，窄屏说明保留一行并省略溢出。深色纸感导航提高图标前景亮度。视图更多菜单从标题栏下方弹出，限制高度并保留滚动与键盘操作；窄屏标签可省略以给更多入口留位。

本轮目标是以更明确的不可发送原因、可扫描的起始任务和稳定的窄屏操作布局超越仅有视觉对齐的基线；是否达到整体 above-floor 标准仍由实机视觉复核判定。没有改变发送、排队、停止、插件权限、服务端接口或流式生命周期。
