# F10.01 — Extended Dynamic Workflow Language & Type Contract

**Round**: F10.01 (扩展动态工作流语言与类型契约)
**Workspace**: `/workspace/xueness-021` — all changes under `ts/packages/agent`.

## Outcome

The dynamic-workflow language now has a **published contract**: a versioned
surface descriptor (`DYNAMIC_LANGUAGE` 1.1) listing exactly which statements,
expressions, operators, spread/destructuring forms, calls, namespaces, globals
and type annotations a public compatible sample may use, plus a diagnostic
registry (`DYNAMIC_DIAGNOSTICS`) covering every compile- and evaluate-phase code
the modules can emit. The compiler and evaluator were widened to accept that
full surface — public compatible samples no longer get rejected by the
previously restricted AST — while ambient TS/Node powers remain explicitly
out of scope and rejected at compile time.

## Contract Invariants Satisfied

- **Public compatible samples compile and evaluate**: every entry on the
  published surface is exercised end-to-end (classic loops, destructuring,
  switch/break/continue, arrows, spread, type assertions, value helpers,
  workflow calls, `args`, `Promise.all` fan-out) with zero diagnostics.
- **No default TS/Node capability**: `process`, `require`, `fetch`, `Date`,
  `console`, `eval`, `Function`, `globalThis` and friends are rejected at
  compile time (`DYN_FORBIDDEN_GLOBAL`); `constructor`/`prototype`/`__proto__`
  are blocked on every access form (`DYN_FORBIDDEN_PROPERTY`); escape attempts
  that parse (e.g. reaching intrinsics through values) still fail at
  evaluation. Unbounded scripts hit `DYNAMIC_BUDGET`.
- **Type contract**: `ask<T>` synthesizes JSON schemas from interfaces,
  literals, unions, records and arrays (including extension, optional and
  nested members) and passes them to the host ask port; unsupported, circular
  and unknown types produce diagnostics instead of runtime surprises.
- **Registry honesty**: the diagnostics registry is asserted in test to match
  the codes the compiler and evaluator actually emit.
