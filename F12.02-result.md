## Contract Invariants Satisfied
- **Browser/tab identity**: every browser and tab gets a stable `b-…`/`t-…` id at creation; all operations address a tab by id and report `TabInfo`/`BrowserInfo` (url, title, navigation counts, creation time).
- **Real navigation, reads and interaction**: the facade drives a `BrowserDriver` port end-to-end — open → navigate → read (title + text) → click (follows `data-href` navigation) → type (echoes the field value) — verified against the bundled fixture driver over real HTML files, which presents the same operations a real automation engine would.
- **Deterministic invalid-reference semantics**: a handle that never existed, outlived `close_tab`/`close_browser`, or followed `dispose` resolves to a `stale_reference` error (never silently hits another tab); downloads recorded before the close stay addressable by id until the facade is disposed.
- **Download artifacts and persistent references**: downloads land as files outside the workspace with `d-…` ids that survive further navigation and tab/browser close; screenshots are written into the artifacts directory.
- **Compatibility with the original browser tools**: the single `browsers` tool covers the six fixed browser tools (open, read, click, type, screenshot, close) — the tool test drives all six through the facade, including the stale-reference error after close.
- **Bounded footprint**: caps of 4 browsers and 8 tabs per browser with explicit `too_many_browsers`/`too_many_tabs` errors; `dispose` closes every driver browser and clears all references.
