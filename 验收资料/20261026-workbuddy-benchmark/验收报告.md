## 修复内容

1. `ServerResponse.write()` 返回 false 后，旧 helper 在 socket 暂无压力时立即放行生产者。现在等待实际 drain，并同时检查 response/socket 缓冲状态，断开和取消时清理监听器与迭代器。
2. 真实 WorkBuddy 工具流的结束增量可能为已绑定索引携带空 ID。现在只对已绑定身份把该空提示视作省略，仍拒绝未绑定空 ID、身份替换和跨索引冲突。真实失败帧离线重放和三项新回归验证修复。
3. 指定 `?session=` 的导航曾被已保存分屏选择覆盖。初始 URL 现在作为明确的会话选择处理，普通重启继续恢复既有分屏。

4. 后台进程输出已结束但日志文件还未关闭时，读取接口现在仍等待既有的 200 ms 日志收尾预算。可控文件收尾夹具证明原代码失败、新代码通过，正式安装运行时另有 8 轮真实子进程日志上限验证。

这些改动保持现有插件归属。后端共享传输/协议属于基础设施，UI 改动只协调导航，没有新增产品功能。

正式安装与可运行目录包均已更新后端和 Web 构建；EXE 未替换成其它版本，SHA-256 为 `f62900680f24ecb332dcbfdd7d06275540ab67556fbb59d6da002af661760e7c`。覆盖后端时 2,498 个用户文件逐字节未变，基准使用独立数据目录。原程序、后端模块和 Web 资源均有本机备份。

## 真实模型与方法

使用正式安装的桌面程序，通过现有 WorkBuddy 号池与 OpenAI 兼容提供者配置进行完整工具循环。实际目录和响应的模型 ID 均为 **`minimax-m3.1-flash`**，每次生成请求均发送 **`reasoning_effort=max`**；用户原文的 flesh 按目录中的 flash 执行。内置 WorkBuddy 插件的旧模型列表没有改成一个虚构的新入口，正式用户提供者配置没有被基准配置替换。

初始 A/B 并发，随后执行 C 及同会话续跑。逐项审批文件写入/命令，原始工作区和账号配置分开保存。输入为真实公开仓库快照 `18b7bd2` 与合成账务数据，模型调用、命令、文件修改和持久化均真实发生。

每轮 20 步/900 秒，每项原定最多 3 轮，全局最多 120 次生成请求。初始 60 次请求使用 128K 上下文/16K 输出，后续 60 次使用 256K/32K，推理档位始终为 max。更高额度被桌面配置校验拒绝，未发出模型请求。参数改变、预算与驱动修复均保留，结论范围是这次持续任务和恢复演练。

## 停止、恢复与资源

真实 UI 点击停止约 **527 ms** 后进入 stopped；在途上游请求取消。完整关闭桌面进程后重新启动，恢复同一会话，**19 条消息逐条一致**，继续原有工具运行。仍有待处理工具时插入新消息被 409 拒绝，随后通过继续原运行恢复。

驱动曾漏处理异步首次设置弹窗、中文时限文本和持久分屏选择，失败现场保留。最后一项进一步复现为实际 UI 导航缺陷，已修复并在正式构建中复测。其余修正属于测试驱动，未改模型产物。

共 352 次资源采样，每 10 秒一次，采样在压测开始后启动且有重启间隔。驱动与子进程工作集求和峰值 **4.02 GiB**，私有提交峰值 **3.79 GiB**；16 GB 主机空闲物理内存最低约 **617 MiB**。跨进程工作集可能重复计算共享页，既有号池与用户其它应用不在该进程树内。这反映明显内存压力，单次采样不足以判断内存泄漏。
