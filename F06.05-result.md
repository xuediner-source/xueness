## Deliverable → Implementation

- **Form and URL elicitation** — `responseFor` accepts `elicitation/create` with a JSON-Schema `requestedSchema`; string fields with `format: "uri"` are validated (`formatOk`) on both TS and webapp sides, so URL answers are accepted and cleaned.
- **Concurrent requests** — one bounded queue per `stateDir + session` (`MAX_QUEUE = 4`); requests beyond the bound get an immediate standard `decline` result (`busy` diagnostic). The HTTP surface serves the queue head, resolves any open request by id, and refuses mismatched ids with 409.
- **Cancellation** — `resolveElicitation` (accept/decline/cancel) and `cancelServerElicitations` (a dropped connection cancels only its own server's parked requests, not the full session). Timeouts degrade to a standard `cancel` result. Unattended contexts (plan mode, read-only, children, `sub-*` sessions, missing state dir) decline immediately.
- **Session recovery** — the queue head is published atomically (temp file, 0600, fsync) to `<stateDir>/mcp-elicitations/<session>.json` with a 600 s expiry; after a host restart `pendingPublic` recovers it from disk, expired/oversized rows are dropped, and `resetElicitationState` cancels every parked request for a state dir.
- **Tool-call attribution** — servers that echo `_meta.relatedRequestId` (the tools/call id that raised the elicitation) get the request attributed via `ElicitationContext.toolCallOf`; unknown/absent ids leave `toolCall` null, which the tests assert.
- **Reject/cancel standard results** — every path answers the server with a well-formed JSON-RPC result `{ result: { action, content? } }` (or `-32601` errors for unsupported methods / disabled elicitation), asserted by tests.

## Contract Invariants

- Requests are attributed to the raising tool call only via the echoed `_meta.relatedRequestId`; no guessing from ordering (tested: unknown/absent related request leaves `toolCall` null).
- Decline/cancel/timeout produce standard MCP elicitation results (tested: "decline and cancel stay standard results").
- Pending interactions survive a host restart via the durable published row and expire rather than answer stale (tested: recovery + expiry rows).
- A dropped connection cannot leave requests parked for the full user wait (tested: per-server cancel + `resetElicitationState`).
