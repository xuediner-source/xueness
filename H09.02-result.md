## What the round delivers

Acceptance for H09.02 — "matches reuse H01 prefix-cache; isolate failures" — is met by `runMatch` / `runTournament` / `stableAppendTask`:

- **Shared prefix-cache reuse**: one `PrefixCache` instance (H01.03) serves the whole tournament. Each playing model records its turns through the injected `ctx.record`, which wraps `cache.record("<matchId>/<model>", model, request)` and counts hits/misses per side. `runTournament.cacheMetrics` aggregates the run's `PrefixMetrics` across every match and model, and an external cache can be injected so callers own the cache lifetime (asserted: replaying the same tournament on the same cache doubles every model's request count exactly).
- **Match execution**: `runMatch` plays both sides of a bracket match through an injected `MatchTask` (returns a finite score). Higher score wins; a strict tie goes to the better seed (slot 0), keeping outcomes deterministic. Side results carry score, request count, cache hits/misses, and error.
- **Failure isolation**: a task that throws — or returns a non-finite score — fails only that side (`ok: false` with the message); the opponent wins by `forfeit` and the tournament continues. When both sides fail the match is a `double_forfeit` with no winner; `runTournament` then stops advancing that branch and ends the loop with `complete: false` and `champion: null` instead of crashing or spinning (a stall guard plus an optional `maxMatches` cap bound the loop).
- **Default workload**: `stableAppendTask(turns)` plays the H01 stable-append pattern (each request extends the previous conversation); with it, every turn after the first is a cache hit (asserted: 1 miss, `turns - 1` hits per side), and equal play reproduces byte-identical results and metrics across runs (asserted via `deepEqual`).

## Contract invariants satisfied

- **H01 reuse, not reimplementation**: the runner imports `createPrefixCache` and measures hits exactly as production sessions do; session keys are scoped `<matchId>/<model>` so sides never pollute each other's sessions (asserted: 6 distinct keys for a 4-model tournament).
- **Determinism**: no I/O, no clock, no randomness; scores come from the task, ties resolve by seed order, and identical inputs produce deep-equal results and cache metrics (asserted).
- **Isolation**: per-side try/catch (throwing task, non-finite score) and per-match isolation (double forfeit never aborts the run; the run terminates with structured `complete: false`). A failing model loses by forfeit while the rest of the bracket plays to a champion (asserted).
- **Bounded termination**: every `runTournament` path ends — bracket complete, stall (no match decided in a pass), or `maxMatches` cap (asserted: cap of 2 plays round 0 only, `complete: false`, `champion: null`).
- **Bracket purity**: the runner only advances matches through H09.01's validating `recordResult`, so every bracket invariant (valid winner, ready-only transitions, immutability) still holds.
