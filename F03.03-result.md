## Files Changed

- `ts/plugins/sessions/src/steering-priority.ts` (new): Priority scheduling for current-turn guidance admission. `guidanceCommandKind` classifies an inbox item as a `start_now` takeover (live `reserved`/`claimed` send-now promotion) or a plain `steer_guide`; `boundaryAdmissionOrder` returns the deterministic boundary admission order (takeover first, then durable FIFO, stable for equal priorities) by reusing the F03.01 `commandPriority` table from `@xueness/agent`; `preservedInWaitWindow` states the preservation rule for compaction/waiting-tool windows; `guidancePriority` exposes the receipt-facing priority class.
- `ts/plugins/sessions/src/steering.ts`: `beforeModelRequest` now admits eligible same-turn guides in `boundaryAdmissionOrder` instead of raw record order, takes a new optional `boundary` argument (`"model_request"` | `"final_response"`), stamps the journaled guide message with `_input_boundary`, and persists `delivered_boundary` on the settled inbox row so every admission is traceable to the boundary that injected it. Deduplicate/pause/CAS/idempotent-replay logic is unchanged.
- `ts/plugins/sessions/src/steering-runtime.ts`: The runner-owned extension passes the boundary tag — `model_request` at each model step, `final_response` for the text-only close late check — keeping the "at most one guide per boundary, no re-admission of the same guide" behavior.
- `ts/plugins/sessions/test/steering-priority.test.ts` (new): 4 unit tests.

## Contract Invariants Satisfied (C-WFL-02)

- A running turn admits **at most one guide per model boundary**; a live send-now takeover is admitted before older FIFO guides (priority scheduling), and plain single-guide turns are byte-identical to the previous FIFO behavior (stable sort, no promotion → same order).
- After a text-only close, **late guidance is still checked** (`beforeFinalResponse` → `beforeModelRequest(..., "final_response")`) and the same guide is **never admitted twice** (verified end-to-end in tests).
- Receipt semantics stay stable (`queued`/`completed`/`paused`, persistent FIFO, CAS, cross-process lease); the new `delivered_boundary` marker is additive.
- Inputs submitted while the run is inside a **compaction or waiting-tool window** of the turn they target stay `queued` (preserved) and trackable via the durable inbox snapshot; already-journaled guides remain trackable after compaction because delivery detection scans both current and archived messages.
