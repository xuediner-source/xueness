# F03.05 Result — Unified Background Task Notifications & Idle Behavior (C-WFL-04)

- **Status**: Completed

## Files changed

- `ts/plugins/subagents/src/background-receipts.ts` (new): durable, exactly-once terminal receipts for delegated subagent tasks. A task that reached `completed`/`failed`/`cancelled` without being collected produces one hidden notice keyed `subagents:<task>:<status>` (namespaced so shell task keys can never collide), capped at 8 per batch. Delivery is stamped on the durable `task_runs` row (`notified`), and a failed journal save rolls both the messages and the stamps back so the reminder is resent later. Notice content carries status facts and the `task_collect` instruction only — the untrusted child summary never becomes notice content.
- `ts/plugins/subagents/src/index.ts`: merges receipts at the two safe boundaries (`beforeModelRequest`, `beforeFinalResponse`). Each boundary first mirrors the coordinator's live registry into the session journal (`coordinator.sync()`), then merges; the hooks are inert without a bound coordinator, and the final boundary reports "continue the loop" only when a new notice actually merged.
- `ts/plugins/workflows/src/dynamic-blocked-reminder.ts` (new): live-run blocked reminders mirroring upstream `dynamic-workflow-blocked-reminder`. Only a run actually paused on a pending actor question or JSON hole (`awaiting_user` run with an `awaiting_user` ask/hole node) produces one descriptor keyed `dwf:<run>:awaiting_user:<node>`; reminders are pure descriptors, the host owns the journal.
- `ts/plugins/workflows/src/dynamic-service.ts`: `blockedReminders(sessionId)` exposes the session's deduped reminder set.
- `ts/plugins/workflows/src/dynamic-tools.ts`: `workflow_script_status` carries the run's `blockedReminder` and `workflow_script_list` carries the deduped `blockedReminders`, both pointing at the existing `workflow_script_resolve` path.
- `ts/plugins/workflows/src/index.ts`: exports the new module.
- Existing foundation verified unchanged: `ts/plugins/shell/src/background-runtime.ts` (terminal/lost notices deduped by `id:state`, lost runners marked lost without guessing results, save rollback) and the sessions turn-merging surfaces (`turn-runtime.ts`, `completion-policy.ts`, `fork-boundaries.ts`, `rewind.ts`, `forking.ts`) that project `_input_kind: "background_notice"` messages as system activity.

## Contract invariants satisfied

- **One effective reminder after parent resume**: the durable `notified` stamp plus key dedup across current *and* archived messages means a resumed or restarted parent sees each task's terminal state exactly once, ever — including after compaction when the stamp row is gone.
- **Hidden reminders never become user input**: every notice is `role: "user"` with `_input_kind: "background_notice"`, `_meta_source: "task_status"`, and wrapped as a system reminder; sessions turn merging, completion policy, rewind and forking all exclude this kind from human-input accounting.
- **No busy-wait when idle**: a boundary with no pending notices performs no save and does not continue the model loop; count-only changes (steps, events growth, wait bookkeeping) stay silent by construction — only `awaiting_user`-on-node (workflows) and terminal status (subagents/shell) can ever notify.
- **Merges only at safe boundaries**: before a model request and at final-response time, matching upstream's reminder-queue semantics on the existing notification facility.
