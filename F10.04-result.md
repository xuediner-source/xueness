# F10.04 — Implementing world.run and World Reads

## Summary

F10.04 delivers the public world SDK for the dynamic workflow engine in `ts/plugins/workflows`: `WorkflowWorld` registers typed workflows and runs them via `world.run(name, args)` (host entry) or `ctx.run(...)` (nested executors), with full run ownership records, attributed world reads, input-versioned result caching, and a per-root cross-actor shared context.

## Files Changed

- `ts/plugins/workflows/src/dynamic-world.ts` (new, ~185 lines): the world module.
  - `WorkflowWorld.register/run`: workflow registry plus the public `world.run(name, args, { actorId })` entry point; executors receive a `WorldRunContext` with `run` (nested runs), `read` (world reads), `share`/`shared` (cross-actor context), and live `usage`.
  - `WorldRunRecord` ledger: every run — root or nested — records `runId`, `parentRunId`, `rootRunId`, optional `ownerActorId`, input fingerprint/version, cache outcome, status, result/error, and timestamps; `records()`, `record()`, `children()`, `readLog()` expose the audit trail.
  - `inputFingerprint`: canonical JSON (object keys sorted recursively, arrays order-preserving) hashed with SHA-256, so `{a:1,b:2}` and `{b:2,a:1}` are one input version while any value change misses.
  - Input-versioned cache: per-workflow entries keyed by fingerprint with LRU-style eviction at `cacheLimit` (default 8); disabled per-spec via `cache: false` or globally via `cacheLimit: 0`.
  - `WorldRunUsage` accounting per run (asks/reads/subruns/cacheHits/cacheMisses); nesting guarded by `maxDepth` (default 8).
- `ts/plugins/workflows/test/dynamic-world.test.ts` (new): 13 tests.
- `ts/plugins/workflows/src/index.ts`: re-export `dynamic-world.ts`.

## Contract Invariants Satisfied

- **The public SDK sample runs**: register + `world.run` executes a workflow, returns its result, and records the run; unregistered workflows and blank names/non-function executors are rejected.
- **Sub-run ownership and usage are traceable**: child runs carry parent/root run ids and the owning actor id, appear in `children()`, and bump the parent's `subruns` usage; every world read logs run/root/actor attribution and per-run `reads`.
- **The cache follows input versions**: identical inputs replay (1 execution, `cached: true`, cacheHit counted); key-order-equal objects are the same input version; changed inputs miss and re-execute; `cache:false` and `cacheLimit: 0` both disable; eviction beyond `cacheLimit` re-executes the evicted input.
- **Cross-actor context is scoped per root run**: values shared inside one root run are visible to sibling actors in that root and invisible to other roots.
