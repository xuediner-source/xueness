## What the round proves

Acceptance for H08.02 — "hooks can trigger auto-verify/self-repair" — is covered by one edit story end to end, with real child processes on both plugin sides:

1. The H01 loader mounts a harness whose manifest declares `hooks: [{ event: "after_tool_execution", handler: "auto-verify" }]` and a `signal-gate` verifier.
2. The host maps that declaration onto a hooks-plugin plugin contribution (`registerPluginHooks`); the F07.03 boundary admits it with the default (absent) boundary file as `plugin:deepseek_harness:auto-verify`, and refuses the identical declaration when `hook-boundary.json` withholds trust (`plugin_not_trusted`, zero admitted rows).
3. `hooksExtension` (`legacy: true`) fires the declaration as a PostToolUse hook after an `edit` tool call, executing it through the plugin's real scoped process executor (`scopedExecute` over a kernel `Context`); the failing gate (exit 1) is recorded in `session.hook_log` with metadata only, and the hook's process scope closes with the run.
4. The same gate command runs through H02.01 `createAutoVerify` with the production `spawnGateRunner`: `0/1 gates passed; failed: signal-gate`, exit 1, and 60 noise lines compressed behind the `… lines omitted …` marker under the 4000-byte cap.
5. The H02.02 `runSelfRepairLoop` consumes that verify pass: the repair callback sees the compressed diagnostics, rewrites `signal.txt`, and the loop goes green in exactly 2 attempts (`status: "passed"`).
6. After the repair, the same PostToolUse hook fires exit 0 — hooks and auto-verify observe one gate.
7. A declined repair terminates the loop immediately as `gave_up` (bounded termination).

## Contract invariants satisfied

- Hooks never grant themselves trust: plugin hook rows only run while the boundary admits the contributing plugin; a withholding boundary disables the same declaration.
- Hook execution is argv-only in the session workspace through the scoped executor, never a shell; failures are recorded as structured `hook_log` metadata (event, id, exit code), never raw output.
- Auto-verify stays deterministic and bounded: compressed diagnostics (head/tail omission marker, byte cap) instead of raw command output; `watch`-selected gates.
- Self-repair is a bounded loop: every path terminates (`passed`, `exhausted`, `gave_up`); a `null` repair ends it without another verify round.
- The harness side stays declarative: the hook/verifier arrive as manifest data via the H01 loader; nothing from the harness source is imported or executed.
