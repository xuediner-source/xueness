# F10.02 — Workflow VM / Harness

**Round**: F10.02 (建设工作流 VM/Harness)
**Workspace**: `/workspace/xueness-021` — all changes under `ts/packages/agent`.

## Outcome

The dynamic-workflow language now has a real production harness,
`runDynamicHarness`, that hosts launch directly: it compiles the script, runs
it under the evaluator, and enforces the four VM guarantees the round demands —
explicit world ports, an injectable clock, cancellation and wall-clock
deadlines, and operation/port-call budgets. `runDynamicHarness` never throws
for script-side failures: every failure is returned as a coded result
(`DYNAMIC_TIMEOUT`, `DYNAMIC_CANCELLED`, `DYNAMIC_BUDGET`, `DYNAMIC_PORT`,
`DYNAMIC_EVALUATION`, or a compile diagnostic), so hosts can log, meter and
retry without try/catch walls. Only invalid harness configuration (bad
`budget.portCalls` / `timeoutMs`) rejects the call itself.

## Contract Invariants Satisfied

- **Real host production launch**: the full-workflow test drives the harness
  the way a host would — `agent()`, `ask`, `files.read`, `log`, `phase`,
  `hole`, `report` all execute and return values, with the exposed port list
  and usage counts reported on the result. Scripts never see the clock, the
  signal or host objects; only `args` and the published globals.
- **Timeouts and cancellation terminate the run**: a script suspended on a
  never-settling port call is ended by the wall-clock watchdog
  (`DYNAMIC_TIMEOUT`, `usage.deadline`, `elapsedMs` measured on the injected
  clock) or by the host's AbortSignal (`DYNAMIC_CANCELLED`) — verified
  deterministically with `ManualDynamicClock.advance()`.
- **Capabilities only through explicit ports**: with no ports registered every
  workflow call fails with `DYNAMIC_PORT` before host code runs; a port that
  does not declare an operation rejects it (`DYNAMIC_PORT`); compile
  diagnostics abort the run before any port is touched.
- **Budgets**: `budget.portCalls` caps cross-port calls (the third of three
  asks never reaches the port) and `budget.operations` caps compute-only
  scripts (`DYNAMIC_BUDGET`).
- **Error propagation**: awaited port rejections surface upstream messages as
  coded results; fired side effects (`report`) are awaited before the result
  resolves and a rejecting side-effect port fails the run with
  `DYNAMIC_PORT: world port rejected the call`.
