## Deliverable → Implementation

- **协议桥 (protocol bridge)** — the client declares the Apps capability in `initialize` only for opted-in servers; `appsResponseFor` answers server-side `apps/connect`/`apps/disconnect` with well-formed JSON-RPC results (`accepted: true` + `generation`/`connectionId`, or `accepted: false` with a reason for unattended sessions and `-32601` for disabled hosts / unknown methods); `apps-http.ts` exposes the frame-facing session bridge.
- **资源打开 (resource open)** — `openAppsResource` accepts only bounded printable `ui://` uris, resolves the owning connection across the session's servers, and returns the manifest (`uri`, `appId`, `iframeUrl`, `version`, `tools`) only when the guard matches and the connection is connected; the HTTP surface maps this to `POST open_ui` with `400/404/409` outcomes.
- **Apps iframe/视图 (app view)** — `AppsFrame` renders a sandboxed iframe (`allow-scripts`, no same-origin) with an app bar (name, ui resource/app id, close) and the app-provided tools list; frame urls are restricted to `https:` or loopback `http:` origins on both server (`frameUrl`) and webapp (`isSafeAppsFrameUrl`) sides.
- **连接等待 (connection wait)** — `waitForAppConnection` parks with bounded 200 ms wake granularity up to the deadline, re-validating lease and generation before parking and after every wake; the HTTP GET long-wait (≤ 20 s) serves the same for the webapp with plugin-availability rechecks each loop.
- **lease generation 复核 (recheck)** — every `appsConnect` (including reconnects) advances the generation and wakes prior waiters; every state-changing call (`appsReady`, `openAppsResource`, `appsToolContext`, HTTP `app_ready`/`open_ui`/`tool_context`) re-checks `connectionId + generation`, so a stale frame receives `409 stale` and can never reach the new session; `appsDisconnect` from an older connection is ignored for the current entry.

## Contract Invariants (C-ADJ-03)

- The `ui://` Apps resource is hosted by the host and gated by the session lease + connection generation (tested: "opens ui:// resources and exchanges tool context only under the live generation").
- Apps tool visibility follows connection state: tools are exposed only while `status === "connected"` (`appsToolsVisible`; tested by the lifecycle test) and the frame drops when the connection closes.
- After a reconnect the old app frame cannot reuse the new session: the generation advances, prior waiters wake to `stale`, and stale guards are refused (tested: "a reconnect advances the generation and refuses the previous app frame" and "refuses stale generations").
- `waitForAppConnection` re-validates the lease after waking (tested: "waitForAppConnection re-validates the lease after waking"); timeouts and closed connections report standard reasons instead of stale data.
- The Apps client capability is declared only for servers opted in with `apps: true` (tested: "declares the apps client capability only for opted-in servers").
