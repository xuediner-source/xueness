# F05.04 Result — Background Execution Output & Recycling (C-TOOL-08 lifecycle)

## Deliverable

Incremental logs, exit codes, artifact references (log paths), terminal
environment initialization and recycling, all linked to the new
foreground→background lifecycle: a parent session that resumes can continue
reading where it left off, large output stays bounded, and exit vs timeout
reasons are never confused.

## Design

- **Complete logs, incremental reads.** Output the model already saw in
  the foreground goes into the task's log files only (`bytes` counts it,
  `unread` does not), so `exec_output` after the handoff returns only
  post-handoff output while the log file still contains the whole stream —
  including output that had already spilled to the capture file in the
  foreground (~170 KB case: the spill file is streamed into the log before
  the paused child stream resumes).
- **Bounded output.** The existing per-task bounds now also bound adopted
  tasks: unread chunks keep head and tail in memory, the log stops at
  `maxLogBytes` and the read reports `[stdout: log file is capped …]`
  instead of anything resembling an exit.
- **Exit vs timeout.** An adopted task settles through the same exit/close
  path as explicit background: a real exit reports `exited with code N`
  (tested with `exit 7`), the task's own background limit reports
  `timed out after …; the process tree was killed` — provenance `adopted:
  true` is kept either way.
- **Resumed sessions.** The unread cursor is per task, and visibility is
  per owner: a fresh `ToolEnv` with the same owner id continues reading
  (no reread), another owner gets `unknown_task`.
- **Recycling.** Finished adopted tasks evict with their log files under
  the existing `maxKept` policy; the shell plugin's close path disposes its
  manager, stopping adopted tasks and removing the manager-owned terminal
  init/startup scripts (the init snapshot stays materialized only while a
  task still needs it).

## Contract invariants satisfied

- **父会话恢复后可接续读取** — first session reads post-handoff output
  once; a restarted session (same owner, fresh env) continues without
  rereading; strangers are refused.
- **大输出有界** — unread chunk bounded (head+tail), log capped at
  `maxLogBytes`, capped logs reported as capped.
- **退出和超时原因不混淆** — `exited with code 7` vs `timed out after
  0.7s; the process tree was killed`, both with `adopted: true` kept.
- **任务 ID、日志及完成通知可用** (C-TOOL-08, with F05.03) — log paths
  are artifact references under `artifactsDir/tasks`, and the plugin test
  verifies the durable `_background_task_notice` for an adopted task that
  reaches its own limit.
