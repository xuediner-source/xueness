## Design

- **The matrix is stated where it can be checked, not just in docs.**
  `executionPlatformMatrix(platform)` returns the documented expectation:
  Linux/macOS — POSIX shell, case-sensitive env, process groups,
  group-signal tree kill, exit-hook crash cleanup; Windows — PowerShell,
  case-insensitive env, no process groups, `taskkill /T /F` tree kill,
  host-job-object crash cleanup. Each row matches the mechanism actually
  used by `defaultShell` (`powershell.exe -NoProfile -NonInteractive
  -Command` vs the POSIX shell), the case-insensitive env overlay
  (`execution-command.ts`), `killTree` (`process.kill(-pgid)` vs
  `taskkill /T /F`), and `windows-job.ts`.
- **Targeted probes verify reality, not the table.**
  `probeExecutionPlatform` actually runs things: it spawns the default
  shell with a marker, spawns `sleep 30 & wait` detached in its own group,
  SIGTERMs the group the way `killTree` does and requires the grandchild
  to die (the guarantee every timeout and cancel on POSIX leans on),
  checks the live host job object on Windows (null on POSIX), and whether
  a PTY backend (`nodePty`, ConPTY on Windows when the prebuild loads)
  is available — exec children themselves stay non-interactive (stdin
  closed, `NO_COLOR`, `PAGER=cat`); the PTY serves the terminal plugin.
- **Windows Job Object crash cleanup kept and extended.** The host job
  object with `KILL_ON_JOB_CLOSE` already covered explicitly backgrounded
  children; `#register` now assigns adopted children too, so the F05.03
  lifecycle cannot smuggle a tree past crash cleanup. POSIX keeps the
  exit-hook + group-kill path (`detached: process.platform !== "win32"`).
