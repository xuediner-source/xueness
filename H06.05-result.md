## What was built

`report.ts` consumes the bench-run shape produced by the runner/profiler rounds (one `BenchCaseResult` per case with raw `latencyMs` / `tokensIn` / `tokensOut` / `cacheHits` / `cacheMisses` measurements) and turns pairs of runs into comparable artifacts:

- `summarizeBenchRun(run)` — folds one `BenchRunSummary` into totals (passed/failed counts, latency/token sums, `cacheHitRate`, `successRate`) plus per-case means over passed cases; empty runs fold to zeroes with no division by zero.
- `compareBenchRuns(baseline, current, { regressionRatio? })` — diffs all five tracked metrics (`latencyMs`, `tokensIn`, `tokensOut` lower-is-better; `cacheHitRate`, `successRate` higher-is-better). Each metric gets a signed `deltaRatio` and a verdict `improved | regressed | unchanged` after a relative threshold (default 10%, overridable). A zero baseline against a non-zero current value is an infinite jump. It also reports `flippedToFailed` (ok → failed case ids), `addedCases`, `removedCases`, and an overall `healthy` flag.
- `serializeRegressionReport(report)` — byte-stable JSON via the canonical serializer from `prefix-cache.ts` (sorted keys), so equal inputs always export identical bytes and reports can be stored and diffed verbatim.
- `renderRegressionMarkdown(report)` — the same report as a deterministic Markdown document (title, verdict line, metric table, case-drift lines).

## Contract invariants satisfied

- Pure computation: no I/O, no clock, no randomness (house style for this plugin); determinism is injectable through inputs only.
- Only imports the plugin's own files (`../prefix-cache.ts`), so `check:plugins` import isolation holds.
- Production file stays under the 400-effective-line oxlint budget (`check:lines`).
- Since H06.01–H06.04 had no landed artifacts, `report.ts` defines the `BenchRunSummary` input contract those rounds will emit; H06.06's runner (see H06.06-result.md) already produces exactly this shape, so the modules compose.
